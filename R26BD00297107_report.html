  • 오픈소스·공개SW 우선 원칙: RFP 전반에서 "라이선스 재활용 또는 국산 및 공개SW로 우선 적용"을 명시하여, 상용 Red Hat 라이선스 도입에 불리한 환경
  • WAS 오픈소스 명시: WAS/Application Runtime으로 "Spring Boot 기반 애플리케이션 (Embedded Tomcat 등 내장형 WAS 구조)" 적용 명시. JBoss/EAP 도입 가능성 낮음
  • 통합발주 상용SW 목록에 Red Hat 없음: 통합발주 S/W는 ezPDF Capture AI 1식만 명시되며, Red Hat 제품 없음
  • Kubernetes 관리형 서비스 활용: "CSP에서 제공하는 관리형 K8S로 구성"을 명시하여 OpenShift(OCP) 도입 필요성이 낮음
Red Hat 제안
가능 요소
  • [제안 가능 포인트]
  • 컨테이너·Kubernetes 환경: 사업 전체가 Kubernetes 기반 컨테이너 플랫폼 구축을 핵심으로 하며, OpenShift Container Platform(OCP)이 Kubernetes 관리형 플랫폼으로서 경쟁력 있는 대안이 될 수 있음. OCP는 DevSecOps, CI/CD, 서비스 메시(Istio), GitOps(ArgoCD) 등 본 사업의 핵심 요구사항을 통합 제공함
  • RHEL 제안 가능성: OS 선정이 "Rocky Linux, Ubuntu 등 권장"으로 되어 있으나 확정은 아님. RHEL은 엔터프라이즈급 보안 인증(CC, FIPS)과 국가정보원 보안 가이드라인 준수 측면에서 제안 여지 존재. 특히 공공 클라우드 보안 요구사항 충족 관점에서 경쟁력 어필 가능
  • Ansible Automation Platform: DevSecOps, CI/CD 파이프라인 자동화, IaC(Infrastructure as Code), 클러스터 운영 자동화 요구사항에 Ansible Automation Platform 제안 가능
  • OpenShift DevSecOps 통합: CI/CD 파이프라인 고도화, GitOps 기반 형상관리, 소스코드 품질관리, 컨테이너 이미지 취약점 점검 등 DevSecOps 요구사항에 OpenShift + Quay + ACS(Advanced Cluster Security) 통합 솔루션 제안 가능
  • 서비스 메시 (OpenShift Service Mesh): mTLS 기반 서비스 간 보안 통신, 트래픽 제어·라우팅·로드밸런싱 요구에 OpenShift Service Mesh(Istio 기반) 제안 가능
  • 멀티클라우드/플랫폼 독립성: RFP에서 "서비스 및 기술 독립성 확보를 위한 오픈소스 도입, 멀티클라우드 등 방안 제시" 요구 → OpenShift의 하이브리드·멀티클라우드 전략 어필 가능
  • RFP에 명시된 Red Hat(동의어) 제품명·수량: 없음 (Red Hat 상용 제품명 전혀 미명시)
  • 영업 접근 전략 제언: SI 파트너(사업 수행사)와 협업하여 OCP/RHEL/Ansible을 하부 플랫폼으로 제안하는 간접 영업 전략 필요. 직접 도입 확정 사업은 아니나, 컨테이너·자동화·보안 플랫폼 전반에 걸쳐 제안 여지 존재
