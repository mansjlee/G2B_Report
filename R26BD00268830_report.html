  • 국정과제 23·24(AI 기본사회 실현, 세계 1위 AI정부) 및 과제 95(행복한 일터) 이행

Red Hat 제안
불가능 요소
  • Red Hat 상용 제품명 전혀 미명시: RFP 전문에서 Red Hat, RHEL, OpenShift, Ansible, JBoss, AAP 등 상용 제품명이 단 한 차례도 언급되지 않음
  • "공단표준준용" 조항 제약: 분리발주 대상 S/W(WEB·WAS·보안OS 등) 모두 "공단표준준용"으로 명시 — 공단 기존 표준 SW 목록에 없는 제품은 WinBack 조항(ECR-005) 적용 시 동급 이상 규격·기능·성능 입증 필요
  • OS 선정 권한이 공단에 있음: 보안OS(LINUX) 분리발주는 공단이 별도 구매 예정 — 현재 공단 표준 OS 제품이 Red Hat이 아닐 경우 참여 불가
  • 국가정보원 CC인증 또는 보안기능 확인서 필수(ECR-005): 보안 제품 전체에 국정원 CC인증 또는 보안기능 확인서 필수 — RHEL의 해당 인증 보유 여부가 제안의 전제 조건
  • 클라우드 전환 제외: 본 사업은 클라우드 전환·통합을 고려하지 않음으로 명시 → OpenShift 기반 클라우드 플랫폼 전환 제안 불가
  • 현행 SW 구성 확인 불가: H/W·S/W 구성도 및 현황이 보안사항으로 입회 열람만 가능 (행안부 고시 제2025-1호 제17조) → 현재 사용 중인 OS·미들웨어 제품 목록 사전 확인 불가
  • S/W 납품 주도권 없음: 분리발주 S/W는 공단이 직접 별도 구매 후 수행사에 제공 예정 (소프트웨어 진흥법 제54조 2항) → 주사업자를 통한 S/W 납품 경로 없음
Red Hat 제안
가능 요소
  • 보안OS(LINUX) — 벤더 미지정 분리발주: "보안OS(LINUX)" 1Server × 2식 분리발주 품목으로 명시되어 있으나 특정 벤더 미지정 → RHEL이 국정원 CC인증 또는 보안기능 확인서를 보유한 경우 공단 표준으로 등재 또는 WinBack 제안 가능
  • 컨테이너 구성요소 적용 요구 (ACR-006): "클라우드 컨테이너 구성요소 적용 방안 제시 및 구현(CI/CD 포함)" 명시 → OpenShift 또는 컨테이너 플랫폼 관련 제안 여지 존재 (클라우드 전환은 아니나 온프레미스 컨테이너 환경 적용 가능)
  • 서버가상화 기반 인프라 구현 명시: 가상화 기반 인프라 환경 구현 및 가상화관리제품 보안기능 확인서 필수 유형으로 명시 → RHEV / OpenShift Virtualization 제안 가능성 검토 여지
  • Linux 기술적용계획표 명시 — 벤더 미지정: "UNIX, Linux"가 서버 OS로 기술적용계획표에 명시되어 있으나 특정 벤더 제한 없음; COR-003에서 "개방형 OS 기반, 플랫폼 독립적 개방형 프로그래밍" 원칙 명시 → RHEL 제안 근거 활용 가능
  • 공단 현행 OS 비공개로 RHEL 사용 가능성 배제 불가: 현재 사용 중인 OS·SW 구성도가 보안사항으로 비공개 → 기존에 RHEL 또는 기타 Red Hat 제품이 사용 중일 가능성 있으며, 이 경우 "기존과 동일 제품 증설" 형태 제안 가능
  • Ansible 자동화 플랫폼 제안 여지: CI/CD 파이프라인, 개발·테스트·운영 환경 분리 구축, 배치처리 자동화 등 다수의 자동화 요구사항 존재 → Ansible Automation Platform(AAP) 인프라 자동화 솔루션 제안 가능
  • 메시지 큐(MQ) 제안 여지: FEP 전문 전송대기 관리에서 "DB 또는 MQ 임시 보관·순차 처리" 방식 명시 → Red Hat AMQ(Artemis 기반) 상용 MQ 솔루션 제안 검토 가능
  • RFP 내 Red Hat 제품 명시 현황: RFP 전문에서 Red Hat 상용 제품(RHEL·OpenShift·Ansible·JBoss EAP 등)이 품목으로 명시된 사례 없음 — 직접 명시 근거는 없으나 상기 제안 가능 요소를 통해 공단 담당자 접촉 및 분리발주 목록 확인 후 전략 수립 권장
