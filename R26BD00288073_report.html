Red Hat 제안
불가능 요소
  • 상용 SW 구매 목록 비공개: RFP 본문에 Red Hat 상용 제품(RHEL, OpenShift, Ansible 등)이 구매·납품·증설 품목으로 명시되어 있지 않음 → 높음 판정 근거 없음
  • Rocky Linux 병행 언급: 기존 OS 환경으로 "Linux(Redhat, Rocky등)"이 함께 명시되어 RHEL의 Rocky Linux 전환(무상 커뮤니티 OS) 가능성이 존재하며, EOS 대응이 RHEL 갱신이 아닌 Rocky 이전으로 귀결될 수 있음
  • Oracle DBMS 중심 환경: DBA 필수 자격으로 OCP(Oracle Certified Professional) 명시, Oracle DB 5년 이상 경력자 요구 → Oracle 환경이 고착화되어 있어 Red Hat Data Grid, AMQ 등 미들웨어 제안 여지 협소
  • 특정 HCI 제품 지정: 뉴타닉스(Nutanix) 및 심플리비티(SimpliVity) 운영 경험 필수 조건 명시 → Red Hat Virtualization(RHEV) 또는 OpenShift Virtualization 제안 어려움
  • 유지관리 중심 사업 성격: 신규 SW 도입보다 기존 환경 유지·운영이 사업의 핵심으로, 신규 Red Hat 상용 라이선스 도입 가능성은 제한적
  • 통합발주 SW 목록 미공개: 실제 구매 대상 상용SW 현황은 보안서약서 제출 후 직접 열람 필요 → 현재 시점에서 제안 가능 여부 확정 불가
Red Hat 제안
가능 요소
  • 기존 RHEL 운영 환경 확인: RFP 유지관리수행-001에 "OS(Unix, Linux(Redhat, Rocky등))에 대한 EOS 대응을 위해 가상화 환경으로 이전 지원"이 명시되어 현재 RHEL이 운영 중인 서버 환경 존재 확인 → 기존 RHEL 구독 갱신 또는 신규 RHEL 라이선스 제안 기회
  • OS EOS 대응 = RHEL 갱신 영업 기회: RHEL EOS 발생 시 기존 RHEL 버전 업그레이드(RHEL 8→9 등) 또는 신규 RHEL 구독 전환 제안 가능 — Rocky 전환 방어 포인트로 RHEL의 엔터프라이즈 지원(보안 패치, 24시간 기술지원) 강조 가능
  • Kubernetes 운영 환경 명시: 인력 요구사항(유지관리인력-002)에 "HCI(뉴타닉스 및 심플리비티 경험 필수, 쿠버네티스) 운영 경험자" 명시 → OpenShift Container Platform(OCP) 또는 OpenShift Virtualization 전환 제안 여지
  • 클라우드 전환 지원 요구: 클라우드 전환 기술지원 수행(IaaS, PaaS, SaaS 적용 계획 포함) 및 JDK 1.8 이상 환경 전환 요구 → OpenShift(PaaS), RHEL on Cloud, Ansible Automation Platform을 통한 클라우드 자동화 제안 가능
  • 가상화 이전(U2L, P2V, V2V) 지원: Unix-to-Linux(U2L) 전환 지원이 명시되어 있어 Unix 서버를 RHEL 기반으로 이전하는 과정에서 RHEL 라이선스 신규 도입 기회
  • 연계 솔루션(ESB) 환경: ESB/EAI 기반 시스템 연계 환경에서 Red Hat Fuse(Camel 기반 통합 플랫폼) 또는 AMQ(메시징 미들웨어) 제안 검토 가능
  • 구독형 라이선스 관리 방안 수립 요구: RFP에 "SW 구독형 라이선스에 대한 관리 방안 수립" 명시 → RHEL 구독 관리(Red Hat Satellite) 도입 제안 포인트
  • 오픈SW 기술지원 전문 협력사 구성 요구: "오픈 SW에 대한 정기점검(현장방문) 및 구체적인 기술지원 방안 제시" 요구 → Red Hat 공식 파트너사로서 RHEL 기반 오픈소스 기술지원 역량을 차별화 포인트로 제시 가능
  • RFP에 명시된 Red Hat(동의어) 제품명·수량: "Linux(Redhat, Rocky등)" — 기존 운영 OS 환경으로 언급, 수량 미상 (상세 목록 비공개) / 별도의 명시적 수량 기재 없음
