불가능 요소
  • **S/W 공급 포함 여부**: 사업자가 네트워크·정보보호 장비 및 관리 S/W를 직접 제안·공급해야 하나, 핵심 범위는 통신회선·네트워크·보안장비 임대·운영이며 Red Hat 제품군이 요구사항에 직접 명시되지 않음
  • **경쟁·대체 제품 명시**: Windows Server가 백신관리 서버에 명시적으로 요구됨; 기술적용계획표에 Linux·UNIX·Windows Server가 병렬 OS 옵션으로 기재되어 있으나 RHEL 등 특정 배포판 미지정; 침입차단·IPS·DDoS·NAC·WIPS·EDR·백신·ESM·SOAR 등은 국정원 안전성 검증필 상용 보안제품 영역
  • **기타 제약**: NIA 5단계 스쿨넷 협약 체결 기간통신사업자·정보통신공사업자만 입찰 가능(공동수급 불가); 보안장비는 CC인증·보안기능확인서 필수; 4단계 장비 규격 동일 이상; 장애 시 동일 제조사 동급 이상 신품 교체; Red Hat이 직접 수행하기 어려운 통신사업자 자격·대규모 회선·전국 스쿨넷 운영 체계가 사업 본질

가능 요소
  • **RHEL 적용 가능성(간접·제한적)**: 기술적용계획표 '서버용(개방형) 운영체제'에 Linux 항목이 있어 ESM·통합로그관리·EMS/NMS 등 관리 서버 OS 후보로 RHEL 제안 가능하나, Windows Server가 백신관리에 명시되어 있고 대부분 상용 보안솔루션+전용 H/W 구조라 실질 채택 가능성 낮음
  • **Ansible 적용 가능성(간접)**: 다수 이용기관(1,140여 개소) 네트워크 장비·정책 일괄관리, Netconf/OpenFlow 연동, 구축·전환·유지관리 자동화 요구와 부합하나 Ansible이 RFP에 명시되지 않았고 네트워크 통합관리 상용 솔루션이 직접 요구됨
  • **OpenShift/JBoss**: 클라우드·컨테이너·미들웨어 관련 요구사항 없음, 해당 사업 범위와 불일치
  • **전략적 접근**: 본 입찰의 직접 공급보다는 기간통신사업자·SI·보안 통합사업자 파트너 채널을 통한 RHEL(관리서버)·Ansible(네트워크·보안 운영 자동화) 번들 제안이 현실적이나, 사업 평가 비중이 통신망구축(9점)·시스템구축(8점) 등 인프라 중심(인프라구성 28점)이라 Red Hat 단독 기여도는 제한적임
