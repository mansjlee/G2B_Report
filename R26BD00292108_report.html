Red Hat 제안
불가능 요소
  • Red Hat 상용 제품 미명시: RFP 전체에 RHEL, OpenShift, Ansible, JBoss EAP, AAP 등 Red Hat 상용 제품이 단 한 건도 언급되지 않음
  • 기존 클라우드 플랫폼 고정: KT Cloud(주) 및 NCP(챗봇/DR)를 현재 사용 중이며, 타 클라우드 이전 시에도 CSAP 인증 민간 CSP 조건만 요구(KT Cloud 현행 유지 원칙). 클라우드 플랫폼 자체가 Red Hat 제품과 무관한 환경
  • DBMS는 국산 Tibero 고정: Tibero Tmax 2식이 기존 운영 중이며 재단이 직접 유지보수 계약 체결. Red Hat Data Grid 등 미들웨어 제안 여지 없음
  • WAS는 오픈소스 Tomcat 고정: Apache/Tomcat 16식이 유지보수 계약 대상으로 명시되어 있어 JBoss EAP 전환 제안 현실성 낮음
  • 신규 SW 구매 아닌 운영·유지보수 중심 사업: 직접구매 해당없음으로 명시. 기존 인프라·소프트웨어 유지가 핵심으로 신규 상용 SW 도입 기회가 제한적
  • 대기업 입찰 불가: 중소기업 한정 사업으로 Red Hat 코리아의 직접 수주 불가. MSP/SI 파트너사를 통한 간접 영업 채널 필요
Red Hat 제안
가능 요소
  • RFP 내 Red Hat(동의어 포함) 제품 명시: 없음
  • Linux 서버 OS 미지정 → RHEL 제안 여지: 기술적용계획표(붙임12)에 서버용 개방형 운영체제로 POSIX.0, UNIX, Windows Server, Linux가 병기되어 특정 배포판이 고정되지 않음. 수행사가 클라우드 VM에 RHEL 구독 포함 제안 가능
  • IaaS 클라우드 환경 → OpenShift/RHEL 제안 가능성: 클라우드 인프라 구성 시 서버 OS 및 컨테이너 플랫폼을 제안사가 결정할 수 있어, RHEL + OpenShift Container Platform 도입 제안 검토 가능 (비용 경쟁력 확보 전제)
  • 24×365 인프라 자동화 니즈 → Ansible Automation Platform 제안 여지: 클라우드 서버 OS 패치·업그레이드, 보안 취약점 조치, 형상관리 등 반복적 인프라 운영 자동화에 Ansible AAP 적용 제안 가능
  • 보안 모니터링 요구 → ACS 제안 여지: 컨테이너 기반 서비스 확장 시 Red Hat Advanced Cluster Security(ACS)로 보안관제 통합 제안 가능
  • MSP 파트너 협력 기회: 수행 MSP/SI 업체가 Red Hat 파트너일 경우 인프라 구성 단계에서 RHEL 구독 포함 제안 가능. 파트너 발굴 및 공동 영업 전략 수립이 현실적 접근법
