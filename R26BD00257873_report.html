불가능 요소
  • **S/W 공급 미포함**: 본 사업은 H/W·상용 S/W 조달이 아닌, 기 구축된 사회보장정보 통합플랫폼(행복이음·복지로·희망이음) 내 기능 개발·연계 고도화가 핵심 과업이며, Red Hat 제품을 직접 납품·라이선스 공급하는 조달 항목이 없음
  • **경쟁·대체 기술 명시/고정**: VMware·Contrabass·Ubuntu·Oracle/Rocky Linux 등 특정 OS·가상화 제품은 RFP에 명시되지 않았으나, 기술적용계획표상 서버 OS는 Linux·UNIX·Windows Server 등 개방형으로 기재되어 있고, 실제 구현은 전자정부 표준프레임워크(Java)·발주기관 ESB·자체 API 게이트웨이 개발(SFR-023)로 규정되어 Red Hat 독점 제안 여지가 제한됨
  • **기타 제약**: 한국사회보장정보원 개발표준·연계표준·PMO·감리·EA(IRM) 현행화 의무, 하도급 50% 제한, 기술적용계획표 준수·개방형 기술 검토 원칙, 기존 운영체계 변경 최소화 전제로 인해 신규 미들웨어·플랫폼 도입은 제안서 기술평가(적용기술 3점)에서 실현가능성·표준 준수 입증 필요
Red Hat 제안
가능 요소
  • **RHEL**: 기술적용계획표 플랫폼 분야에서 서버용 Linux가 적용 대상으로 열거되어 있어, 제안사가 Linux 기반 WAS·DB·연계서버 OS 표준으로 RHEL(구독·지원·보안패치)을 기술제안·하도급/물품구매 계획에 포함할 여지는 있으나 RFP 필수 요구는 아님
  • **Ansible**: 다수 외부·내부 시스템 연계, 배치·API 게이트웨이, 성능·안정화(SFR-026), PMR 안정화·장애대응, 350일 내 1·2차 개통 등 운영 자동화·구성관리 필요성과 부합 — 제안서 ‘적용기술’·‘시스템 통합·운영’ 파트에서 DevOps/자동화 보조 솔루션으로 간접 제안 가능
  • **API·통합·보안 강점**: SFR-022·023의 RESTful API·게이트웨이(인증·권한·트래픽·이력), 17건 보안요구(SER), N2SF·국정원 검증필 암호모듈, 컨테이너/마이크로서비스 전환은 RFP 범위 밖이나, 향후 API 확장·클라우드(PaaS/IaaS 기술적용계획표 적용) 로드맵 제안 시 OpenShift·3scale(API 관리)를 차세대 아키텍처 옵션으로 언급 가능(본 사업 직접 납품 항목 아님)
  • **JBoss 등**: RFP에 JBoss·WildFly 등 WAS 명시 없음. 전자정부 표준프레임워크 기반 Java 응용 개발이 전제이므로 JBoss EAP 직접 제안 가능성은 낮고, 기존 행복이음·희망이음 운영 WAS 스택을 따를 가능성이 큼
