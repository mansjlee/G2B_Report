한국지능정보사회진흥원_2026년 디지털서비스 개방 API 개발 지원사업

1. 사업개요 및 목적

본 사업은 행정안전부 및 한국지능정보사회진흥원(NIA)이 추진하는 사업으로, 공공기관의 앱·웹에서만 제공되던 대민 서비스를 국민에게 익숙하고 편리한 민간 앱에서도 이용할 수 있도록 디지털서비스 개방 표준 API를 개발하고 연계하는 사업입니다.

이를 통해 민간서비스를 활용한 전자적 대민서비스의 편의성과 효율성을 제고하고, 공공부문 AI 도입 및 국민·기업 중심의 서비스 혁신 생태계를 조성하는 것을 목적으로 합니다.

2. 사업 예산, 범위 및 일정

  • 사업예산: 2,948,322,227 원 (부가세 포함)
  • 사업기간: 계약체결일로부터 150일
  • 사업범위:
    • 수요조사 및 확정 결과를 바탕으로 선정된 총 25종의 공공 서비스 분석 및 개방 API 개발 지원
    • (예시 서비스: 내가 먹는 약! 한눈에(건강보험심사평가원), 국악 공연 예매(국립국악원), 모바일 건강보험증 발급 및 조회(국민건강보험공단), 군 신분 확인 서비스(국방부) 등)
    • 표준화 가이드에 맞춘 API 명세서 작성, API 개발, 디지털서비스플랫폼 연계 및 대민 서비스 개통 지원

4. 주요 요구사항 및 기술 특이 사항

  • 표준 API 설계 및 개발: 공공 서비스 데이터의 안전성, 보안성, 확장성을 보장하는 표준 RESTful API 기반 연계 체계 구축
  • 이기종 시스템 연계: 각 공공기관이 보유한 서로 다른 레거시 인프라와 민간 플랫폼 간의 원활한 상호운용성 확보 필요
  • 대용량 트래픽 처리: 대민 서비스 개방에 따른 민간 플랫폼발 대규모 동시 접속 및 트래픽 폭증 시 서비스 안정성 보장

5. Red Hat 제품 제안 불가능 포인트 분석

본 사업의 특성 및 기존 환경 분석에 따라, 다음 항목들은 단순 Red Hat 제품의 직접 제안 및 공급이 어려울 수 있습니다.

  • S/W 직접 공급 사업이 아님: 본 사업의 본질은 API 개발 및 연계 지원 용역 사업으로, 인프라 소프트웨어(S/W) 라이선스를 대량 도입하거나 공급하는 형태의 사업이 아닙니다.
  • CSP (Cloud Service Provider) 기반 인프라: 개방 플랫폼이 특정 CSP 환경 내에서 구축 및 운영되므로, 인프라 아키텍처는 클라우드 서비스 제공업체(CSP)의 PaaS/SaaS 서비스에 종속되어 있어 독자적인 솔루션 구매 계약이 제한적입니다.
  • 기존 인프라 및 경쟁사 솔루션 고착화: 개방 기관 및 민간 연계 기관의 기구축 환경에 따라 가상화 및 OS 단에서 강력한 경쟁 제품군이 명시되어 활용될 가능성이 큽니다.
    • 가상화 영역: 기존 환경에 도입된 VMware 또는 국산 가상화 솔루션인 Contrabass 적용으로 신규 침투 제한적
    • OS 영역: 오픈소스 및 저비용 운영 정책에 따라 무상 사용이 가능한 Ubuntu, Rocky Linux 혹은 기존 라이선스를 보유한 Oracle Linux가 기 운영 중일 가능성 존재

6. Red Hat 제품 제안 가능 포인트 분석

그럼에도 불구하고, 향후 디지털서비스플랫폼 고도화 및 개방 API의 원활한 관리와 유연한 연계를 위하여 장기적인 관점에서 아래와 같이 Red Hat 솔루션의 적용 가치를 제안할 수 있습니다.

  • Red Hat OpenShift (클라우드 네이티브 API 마이크로서비스 아키텍처 구축): 대민 연계 API는 트래픽 변동폭이 큽니다. 컨테이너 기반의 오케스트레이션 플랫폼인 OpenShift를 통해 API 게이트웨이 및 백엔드 서비스를 마이크로서비스(MSA) 형태로 유연하게 배포 및 자동 확장(Auto-scaling)할 수 있습니다.
  • OpenShift Virtualization Engine & Red Hat Virtual Data Center (기존 VM과의 통합): 기존에 VMware나 Contrabass 기반으로 운영 중이던 가상화 워크로드를 컨테이너 환경인 OpenShift와 단일 플랫폼에서 통합 관리하고 점진적으로 마이그레이션할 수 있는 방안을 제시합니다.
  • Red Hat Enterprise Linux (RHEL - 고신뢰성 연계 기반 OS): 민감 정보를 다루는 보건 의료(내가 먹는 약 조회, 건강보험증) 및 국방(군 신분 확인) API 연계 서버의 OS로, 보안성과 규정 준수(Compliance)가 완벽히 보장되고 지속적인 보안 패치를 지원하는 RHEL 도입이 필수적임을 제안합니다. (Ubuntu, Rocky Linux 대비 높은 보안성 강조)
  • JBoss Enterprise Application Platform (EAP - 안정적인 미들웨어 연계): 공공기관 내부 레거시 시스템과 표준 API 간의 트랜잭션 처리 및 안정적인 메시징 전송을 위한 미들웨어로 검증된 성능의 JBoss EAP 제안이 가능합니다.
  • Ansible Automation Platform (다중 API 환경 자동 배포 및 관리): 25종에 달하는 개방 API 서비스의 각 타겟 클라우드(CSP) 환경 배포, 설정 관리, 정기적인 패치 수동 작업을 코드로 관리(IaC)하여 운영 공수를 최소화하는 자동화 도구로서 Ansible 적용을 권장합니다.
