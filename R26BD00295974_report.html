Red Hat 제안
불가능 요소
  • WAS가 WildFly로 명시: SW 목록 5번 WAS 항목이 "WildFly × 1식"으로 명시되어 있음. WildFly는 Red Hat의 커뮤니티·업스트림 제품으로, JBoss EAP(상용)가 아님. 판정 규칙상 WildFly 명시는 높음 판정 불가 → 상용 JBoss EAP 도입 품목으로 볼 수 없음
  • CentOS가 명시: SW 목록 7번 "CentOS CS(HA) × 1식"이 DBMS 이중화솔루션으로 명시됨. CentOS는 커뮤니티 제품으로 RHEL 상용 제품이 아님. RHEL 전환·대체 여지 불확실
  • Red Hat 상용 제품명 미명시: RFP 전반에 걸쳐 RHEL, OpenShift, Ansible Automation Platform, JBoss EAP, Satellite 등 Red Hat 상용 제품명이 품목으로 명시되지 않음
  • 순수 유지보수 용역 성격: 신규 S/W 도입·납품·구독 항목이 아닌, 기존 구축 시스템에 대한 유지보수 용역 중심임. 단, 워런티·라이선스 갱신 대상이 포함되어 있어 완전한 S/W 미포함은 아님
  • 중소기업 제한 입찰: 사업금액 20억 미만으로 대기업 참여 불가 조건이 있어 Red Hat이 직접 참여하기 어렵고, SI 파트너를 통한 간접 참여 구조임
  • 오픈소스 SW 기술지원확약서 허용: RFP에서 오픈소스 SW의 경우 제조사 확약서 없이 유지관리 수행 가능 업체가 발행한 기술지원확약서로 대체 가능하여, 오픈소스(WildFly, CentOS 등)를 그대로 유지할 가능성이 높음
Red Hat 제안
가능 요소
  • WildFly → JBoss EAP 전환 제안 여지: 현재 WAS가 WildFly(커뮤니티)로 운영 중이나, 상용 지원이 필요한 공공기관 환경에서 JBoss EAP(상용) 전환을 제안할 수 있는 여지가 있음. 기술지원확약서 제출 의무 조항이 EAP 전환의 명분이 될 수 있음
  • CentOS → RHEL 전환 제안 여지: SW 7번 CentOS CS(HA)가 DBMS 이중화용으로 운영 중이나, CentOS의 지원 종료(CentOS Linux 8 EOL) 이슈를 활용하여 RHEL 전환을 제안할 수 있는 가능성이 있음
  • 알약 리눅스 서버 86개 → Linux OS 환경 파악 가능: 서버 백신 "알약 1.1 리눅스 × 86개"로 보아 다수의 Linux 서버가 운영 중임. 해당 서버의 OS가 미확정·공개SW 계열이라면 RHEL 제안 가능성 존재 (방문 열람을 통해 현황 파악 필요)
  • 컨테이너 환경(도커&쿠버네티스) 운영: 오픈랩 및 개인정보 비식별화 시스템이 도커&쿠버네티스 기반으로 운영 중. OpenShift Container Platform 또는 OpenShift AI로의 전환·제안 가능성 존재
  • 서버 229식 규모의 대형 Linux 운영 환경: HW 서버만 229식(RX2540 M5 63대, GX2460 M1 16대, HP XL270D Gen10 6대 등) 규모로, 서버 OS 현황 파악 시 RHEL 도입 기회 가능
  • Ansible 활용 가능 영역: 대규모 HW/SW 패치, 주기적 점검, 보안 설정 관리 등 자동화가 필요한 운영 과업이 다수 존재하여 Ansible Automation Platform 제안 가능
  • RFP에 명시된 Red Hat(동의어) 제품명·수량: 없음 (WildFly, CentOS는 커뮤니티 제품으로 상용 Red Hat 제품 아님)
  • 현장 방문을 통한 정확한 현황 파악 권장: RFP상 "상세정보는 방문하여 문의" 안내가 있으므로, 사전 방문을 통해 서버 OS 종류 및 버전, WAS 버전, 컨테이너 플랫폼 현황 등을 파악하여 제안 전략 수립 필요
