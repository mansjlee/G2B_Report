불가능 요소
  • [용역 중심 사업]: 본 사업은 신규 S/W 도입·납품이 아닌 기존 시스템의 유지관리·운영위탁 용역이 핵심으로, Red Hat이 직접 낙찰받기보다 SI·운영사업자(하도급·협력사)를 통한 간접 수주 구조
  • [VMware 경쟁 제품 운영 중]: [붙임6] 예방점검 항목 클라우드 영역에 VMware ESXi / vCenter(vSphere) 가 기존 인프라로 명시되어 RHV와 병존 중 — 완전 교체 기회는 제한적
  • [품명 비공개]: [붙임1] H/W 및 상용S/W 목록에서 품명이 보안상 제외되어 있어 Red Hat 외 경쟁 OS(Rocky Linux, Ubuntu 등) 실제 사용 여부를 RFP 문면상 확인 불가
  • [대기업 참여 제한]: 20억 이상 40억 미만 사업으로 대기업 소프트웨어사업자 참여 불가 → Red Hat코리아 규모에 따라 직접 입찰 제한 가능성
Red Hat 제안
가능 요소
  • [RFP 명시 Red Hat 상용 제품 — 핵심 근거]
    • RHEV-M (Red Hat Enterprise Virtualization Manager): [붙임6] 예방점검 항목 클라우드 영역 "RHV (3개)" 항목에 "RHEV-M 가상화SW 상태 점검", "RHEV-M 가상화SW 로그 점검", "관리포탈 이벤트 메시지 점검" 등 명시 → 기존 RHV 인프라 유지관리 대상으로 확정
    • OpenShift Cluster: [붙임6] 예방점검 항목 클라우드 영역 "OepnShift Cluster (10개)"에 Master·Infra·Router·Worker 노드 상태, CPU·Memory·Container Storage 체크, 시스템 로그, kube-system Pod, openshift-console, openshift-metrics-server, openshift-monitoring (Prometheus·Grafana·Alertmanager), openshift-node, openshift-sdn, openshift-web-console Pod 상태 및 로그 명시 → 운영 중인 Red Hat OpenShift 클러스터 유지관리 대상으로 확정
  • [Kubernetes/컨테이너 운영 요구]: MPR-019 "K8S 운영 및 관리 지원" 요구사항에서 K8S 전문 인력 상시 지원 체계 요구 → OpenShift 기반 K8S 전문 지원 제안 가능
  • [Linux 기반 서버 환경]: 기술적용계획표(붙임4)에 "Linux" 서버 OS 적용 명시 / VDI HOST 서버 228대 분량의 운영체제·운영SW가 포함되어 RHEL 제안 여지 존재
  • [WEB/WAS 미들웨어 유지관리]: 상용SW 유지관리 대상에 WAS SW 다수 포함 → JBoss EAP 등 Red Hat 미들웨어 포트폴리오 제안 가능
  • [AI·데이터 플랫폼 확장]: LLM 서버·STT·TA·AI 운영SW 등 AI 시스템 유지관리 요구 증가 → OpenShift AI / RHEL AI 확장 제안 가능성
  • [운영 협력사 파트너 영업 기회]: 운영사업자(낙찰사)가 RHEV-M·OpenShift 지원을 위해 Red Hat 공인 파트너사를 하도급·협력사로 포함하도록 유도 가능 (COR-011: H/W·S/W 제조사 정식 파트너사 자격 요건 명시)
