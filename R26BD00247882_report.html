사업 개요 및 목적
  • 미술진흥법 제23조에 근거한 통합미술정보시스템(플랫폼) 구축·운영 용역으로, 미술시장 정보(전시·거래·경매·작가·미술서비스업 등)를 수집·관리·제공하는 데이터 기반 통합 관리 체계를 마련하는 것이 핵심 목표이다.
  • 거래·유통 정보의 투명성 확보를 통한 신뢰 기반 미술시장 조성, 재판매보상금 납부·분배 운영·관리 체계 구축, 대국민·관리자 서비스 및 외부기관 API 연계를 통한 정보화 체계 완성이 사업의 주요 목적이다.

Red Hat 제안
불가능 요소
  • 단독 S/W 조달·공급 사업이 아닌 SI 용역 통합발주로, Red Hat 라이선스 단독 판매 구조가 아니며 제안사가 용역 범위 내에서 SW를 포함·부담하는 형태이다.
  • VMware, Contrabass, Ubuntu, Oracle, Rocky Linux 등 경쟁 제품이 RFP에 명시적으로 지정되지는 않았으나, GS인증 국산 보안·DB암호화·검색엔진, 국정원 검증필 암호모듈, 국산 개인정보관리솔루션 등 국내 인증 제품 우선 도입 요건이 Red Hat 단독 제안에 제약이 된다.
  • 전자정부표준프레임워크 4.0+·Java(JDK11) 기반 개발이 필수이며 JBoss/WildFly 등 미들웨어 지정은 없고, CSP 마켓플레이스·SaaS·공개SW 우선 검토 원칙으로 상용 미들웨어 직접 지정 기회가 제한적이다.
  • DB암호화(ECR-003)·검색엔진(ECR-004)은 GS인증 제품 필수로 Red Hat 제품군으로 직접 대체 불가하며, 통계·개인정보·보안 솔루션은 국내 상용 제품 협의 도입 구조이다.
  • 하도급 불허, 중소 SW사업자 전용(대기업·중견기업 제외), 클라우드 이용료 발주처 부담 등으로 Red Hat이 직접 주관사업자로 참여하기 어려운 조건이며, 주로 용역사 제안 인프라·OS·자동화 레이어에서 간접 포지셔닝이 필요하다.
Red Hat 제안
가능 요소
  • RHEL: ECR-002 WEB/WAS/DBMS 클라우드 서버 OS로 RHEL 제안 가능. 기술적용계획표에서 Linux·UNIX·Windows Server 기반 운영환경 적용을 명시하고, POSIX/Linux 호환 운영환경 구성 시 RHEL이 CSP 마켓플레이스 등록 제품으로 제안될 수 있다.
  • Ansible: 클라우드 환경 구성·배포·패치·설정관리, ETL·배치·연계 자동화, 2차 백업환경·장애대응(SLA 3시간 복구) 운영 자동화, 다중 서버(WEB/WAS/DB) 구성 관리에 Ansible Automation Platform 제안 가능.
  • OpenShift: CSR/PaaS 활용 검토 항목 및 컨테이너 기반 확장성 요구(고도화·연증 대비)에 부합하는 선택적 PaaS 제안 가능. 필수는 아니나 민간클라우드 PaaS 구성 시 컨테이너 오케스트레이션·CI/CD·마이크로서비스 확장 방안으로 제시 가능.
  • 기술 강점 일치: CSAP 민간클라우드 보안·가용성·백업·이중화, API·REST 연계, 데이터 파이프라인(ETL)·품질관리, 24×365 운영관제, 공급망·변경관리, 표준화된 가상이미지·API 상호운용성 요구와 Red Hat 클라우드·자동화·엔터프라이즈 Linux 운영 역량이 부분적으로 일치한다.
  • 제안 전략: 용역사 파트너십을 통한 RHEL(서버 OS)·Ansible(운영 자동화)·OpenShift(선택 PaaS) 번들 제안, CSP 마켓플레이스·정품·AS 관계 증빙 제출, 공개SW·오픈소스 관리적·기술적·법적 하자 없음 입증과 병행하는 간접 제안 구조가 현실적이다.
