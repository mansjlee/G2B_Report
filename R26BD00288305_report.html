Red Hat 제안
불가능 요소
  • 신규 S/W 구매·납품 항목 없음: 법제도 자가점검표(붙임)에 "상용SW도입 없음"으로 명시 — 신규 상용 SW 구독 기회 부재
  • 순수 운영·유지관리 용역: 기존 시스템의 운영 유지관리 및 인력 제공 중심 사업으로, SW 신규 도입 예산이 별도로 계획되어 있지 않음
  • Red Hat 상용 제품 전혀 언급 없음: RFP 전체에 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 단 한 건도 명시되지 않음
  • 기존 SW 스택 유지 조건: 33개 Docker 컨테이너(OpenSearch, MariaDB, PostgreSQL, NGINX, RabbitMQ, vLLM, Spring Boot 등 오픈소스 기반)로 구성된 현행 시스템을 그대로 유지·운영하는 것이 과업의 핵심
  • 경쟁·대체 환경: Oracle GoldenGate(DB 연계), Oracle 기반 모니터링(Maxguage), Window Server 등 타사 제품이 기존 스택에 포함되어 있으며 교체 대상이 아님
  • 대기업 참여 제한: 중소기업자만 입찰 참여 가능(20억원 미만 중소SW사업자 지원지침 적용) — Red Hat 직접 입찰 불가
Red Hat 제안
가능 요소
  • RFP 내 Red Hat 상용 제품 명시 없음: RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 RFP에 전혀 등장하지 않아 직접 제안 근거 없음
  • 컨테이너 기반 운영 환경 (간접 제안 여지, 미래 관점): 33개 Docker 컨테이너로 운영되는 생성형 AI 인프라는 향후 Red Hat OpenShift 플랫폼으로의 전환 제안이 기술적으로 가능하나, 현 사업에서는 기존 Docker 환경 유지가 원칙
  • 차세대 플랫폼 구축 사업 기술협력 연계 (간접 기회): 「AI 기반 국민권익 플랫폼 구축」 사업(별도 발주 예정)이 언급되어 있으며, 해당 구축 사업에서 OpenShift, RHEL AI, Ansible 등 Red Hat 스택 제안 기회를 탐색할 수 있음 — 단, 본 사업 자체의 기회는 아님
  • Linux 기반 서버 환경: 컨테이너 운영 서버의 OS가 명시되지 않아 RHEL 제안 여지가 이론적으로 존재하나, 기존 운영 환경 유지 사업 특성상 실질적 전환 가능성은 낮음
  • 종합 평가: 본 사업은 기존 오픈소스 기반 Docker 환경 유지·운영이 핵심으로, Red Hat 상용 제품 도입 기회가 사실상 없음. 향후 차세대 플랫폼 구축 사업 발주 시 별도 영업 접근 권고
