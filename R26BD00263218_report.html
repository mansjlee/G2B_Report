Red Hat 제안
불가능 요소
  • [오픈소스 기반 SW 요건] CTR-002에서 "시스템 SW는 오픈소스 기반 SW를 적용하여야 하며"로 명시 → RHEL은 상용(유료 구독) 제품이므로 이 조건과 충돌 가능성 있음; 발주기관이 무상 오픈소스 의도라면 RHEL 직접 납품 제안이 제한됨
  • [DBMS 경쟁 확정] DBMS를 PostgreSQL로 명시 확정 → Red Hat이 기여하는 오픈소스 DB이나 상용 RH 데이터베이스 제품(Data Grid 등) 납품 기회는 없음
  • [현 OS는 커뮤니티 제품] 현행 시스템 OS가 CentOS 6.10으로 무상 커뮤니티 제품 사용 중 → 고객이 상용 OS 도입에 거부감을 가질 수 있음
  • [Red Hat 상용 제품 미명시] RFP 전체에 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 품목으로 전혀 명시되지 않음
  • [SI 통합사업 구조] 기능개발·클라우드 전환·유지보수를 단일 SI 사업자가 수행하는 구조이므로, 사업자 재량으로 SW 선택 → Red Hat 상용 SW 도입은 사업자 의지에 달림
Red Hat 제안
가능 요소
  • [목표 OS 미지정 → RHEL 제안 여지] 현 CentOS 6.10은 EOS 상태이며, 클라우드 전환 목표 OS가 명시되지 않음 → "오픈소스 기반"을 충족하는 RHEL(또는 고객 협의 하에) 제안 가능; CentOS→RHEL 전환 영업 기회 존재
  • [컨테이너·MSA 기반 클라우드 네이티브 전환 명시] RFP 클라우드 보안대책 섹션에 "마이크로서비스 아키텍처(MSA) 기반의 모듈화, 컨테이너 오케스트레이션, 자동화된 CI/CD 파이프라인, API 게이트웨이 통합관리" 명시 → OpenShift(OCP) 및 Ansible Automation Platform(AAP) 제안 여지
  • [클라우드 인프라 자동화 필요] 클라우드 전환 후 24×365 운영관제, 인프라 자동화, Scale Out/Up 요건 → Ansible 기반 자동화 제안 가능
  • [WAS 전환 기회] 현행 WAS는 Apache Tomcat 7.0.93(EOS) → 클라우드 전환 시 JBoss EAP(엔터프라이즈급 Java EE WAS) 제안 가능; 단 RFP에 WildFly/Tomcat 지속 사용 명시는 없으나 "오픈소스 기반" 요건 고려 필요
  • [RFP 내 Red Hat 제품명 언급 현황] RFP 본문에 Red Hat 상용 제품명(RHEL, OpenShift, Ansible, JBoss EAP 등)은 품목으로 명시된 바 없음 (단, 현 CentOS 6.10이 Red Hat의 커뮤니티 프로젝트에 해당)
  • [SI 사업자 공략 전략] 입찰 참여 예상 SI 기업(LG CNS, SK C&C, 롯데정보통신 등)에게 RHEL, OpenShift, Ansible 솔루션을 하도급·소프트웨어 공급사 형태로 제안하여 간접 납품 추진 가능
