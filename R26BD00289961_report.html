Red Hat 제안
불가능 요소
  • [상용 S/W 납품 품목 없음]: 이 사업은 소프트웨어 개발·구축 용역 중심으로, RFP 내 통합발주 또는 별도 구매 형태의 상용 S/W 품목 목록이 전혀 명시되어 있지 않음. Red Hat 제품의 납품·도입 확정 근거 없음.
  • [Red Hat 상용 제품명 미명시]: RHEL, OpenShift, Ansible, JBoss EAP, Satellite, AAP 등 Red Hat 상용 제품명이 RFP 어디에도 구매·도입 품목으로 등장하지 않음.
  • [커뮤니티 오픈소스 기반 설계]: RFP가 vanilla Kubernetes, 오픈소스 Keycloak, Docker, ArgoCD, Flux, Prometheus, Grafana, Redis 등 커뮤니티/오픈소스 제품을 기준으로 구체적으로 요구하고 있어, 상용 Red Hat 제품으로의 대체 필요성을 발주처가 명시적으로 인식하지 못하고 있음.
  • [순수 개발 용역 성격]: 사업의 핵심 산출물이 소스코드, 설계서, 운영 매뉴얼 등 개발 결과물이며, 물품 납품보다 용역 수행 중심의 계약 구조임.
  • [경쟁 제품 명시 여부]: Ubuntu, Rocky Linux, VMware, Oracle Linux 등 직접 경쟁 OS/플랫폼이 명시적으로 지정되지는 않았으나, 특정 OS가 지정되지 않은 상태에서 수행사가 오픈소스 OS를 선택할 가능성 존재.
Red Hat 제안
가능 요소
  • [OpenShift Container Platform 제안 여지]: RFP 전체가 Kubernetes 기반 컨테이너 오케스트레이션 환경을 요구하므로, OpenShift Container Platform(OCP)을 Kubernetes 배포판으로 제안 가능. OCP는 엔터프라이즈급 보안(RBAC, OIDC, NetworkPolicy), GPU Operator, 내장 모니터링 스택 등을 제공하며 요구사항과 부합.
  • [RHEL 제안 여지]: RFP에 워커 노드·컨트롤 플레인의 운영체제(OS)가 명시되지 않아 RHEL 또는 RHEL CoreOS(OCP 기반) 제안 가능. GPU 드라이버 안정성과 기업 지원 측면에서 강점 부각 가능.
  • [Red Hat SSO(Keycloak 상용) 제안 여지]: RFP 전반에 걸쳐 Keycloak(OIDC) 기반 SSO가 핵심 인증·권한 관리 체계로 명시(SFR-001, SFR-003, SFR-004, SIR-003 등). 오픈소스 Keycloak 대신 Red Hat SSO(상용 지원 제공) 또는 Red Hat Build of Keycloak을 제안하여 기업급 지원 SLA 차별화 가능.
  • [OpenShift GitOps / OpenShift Pipelines 제안 여지]: RFP에서 ArgoCD/Flux 기반 GitOps(SFR-003)와 MLOps 파이프라인 자동화가 명시적으로 요구되며, OpenShift GitOps(ArgoCD 기반 상용화)와 OpenShift Pipelines(Tekton 기반) 제안 가능.
  • [Ansible Automation Platform 제안 여지]: GPU 노드 프로비저닝, Kubernetes 클러스터 설치·유지관리, 보안 패치 자동화 등 인프라 자동화 요소에 대해 AAP 제안 가능.
  • [OpenShift AI / RHEL AI 제안 여지]: MLOps SaaS 구축(Kubeflow, vLLM, Triton 기반 AI 모델 개발·학습·배포) 요구사항은 OpenShift AI(RHOAI)와 기능적으로 높은 연관성이 있어 제안 경쟁력 확보 가능.
  • [RFP 내 Red Hat(또는 동의어) 제품명 명시]: RFP 본문 내 Red Hat 상용 제품명(RHEL, OpenShift, Ansible 등)은 직접 명시되지 않음. Keycloak은 오픈소스 버전으로 언급됨.
  • [영업 전략]: 수행사(SI) 선정 후 세부 기술 스택 협의 단계에서 Red Hat 솔루션을 제안하는 SI 파트너 영업 전략이 효과적. 사업 규모(약 28.5억)와 기간(약 8개월)을 고려할 때, OCP + RHEL + RHOAI 패키지 제안으로 접근 권장.
