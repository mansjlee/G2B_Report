불가능 요소
  • 데이터베이스 지정: SQL Server 2022 이상으로 명시 지정 — RHEL 기반 DB(PostgreSQL 등 Red Hat 스택)로의 대체 불가
  • WEB/WAS GS인증 필수: RFP ECR-001에서 WEB 및 WAS 모두 GS인증 취득 제품을 요구 — JBoss EAP는 한국 GS인증 미보유로 WAS 품목 직접 제안 어려움
  • 국내 인증·조달 요건 중심: UI/UX 개발 Tool(GS인증·전자정부 표준프레임워크 호환성 인증), 리포팅 Tool(GS 1등급·조달청 우수제품 인증) 등 국내 특화 인증이 필수로, Red Hat 제품군이 해당 인증을 보유하지 않음
  • Red Hat 상용 제품명 전혀 미기재: RFP 전문에 RHEL, OpenShift, Ansible, JBoss EAP, Satellite 등 Red Hat 상용 제품명이 구매·납품 품목으로 명시된 사례 없음
  • 경쟁·대체 OS 없음 / 커뮤니티 제품 미기재: Ubuntu, Rocky Linux, CentOS, WildFly 등 경쟁 제품도 명시되지 않아 "낮음" 판정 요인도 없으나, 동시에 Red Hat 상용 제품 확정 근거도 부재
  • SSO 제품 고가용성·이중화 요건: SSO 솔루션은 국내 상용 제품 중심으로 제안할 가능성이 높으며, Red Hat SSO(Keycloak 상용)의 국내 레퍼런스·인지도 측면에서 경쟁 열위 우려
Red Hat 제안
가능 요소
  • 서버 운영체제 미지정: RFP에서 서버 OS를 특정하지 않고 "공공 클라우드(G-Cloud) 포함 구성 제안"을 요구 → RHEL을 운영 OS로 제안 가능. 기술적용계획표 상 Linux(서버용 개방형 OS) 항목이 명시되어 있어 RHEL 제안 근거 확보 가능
  • Java/WAS 환경에서 JBoss EAP 가능성: Java EE 8 이상, 전자정부 표준프레임워크 지원 WAS를 요구하며, JBoss EAP는 해당 기술 요건을 충족 — 단, GS인증 미보유 이슈를 파트너사의 GS인증 WAS(티맥스소프트 JEUS 등)와 번들링 전략 또는 컨소시엄 방식으로 접근 필요
  • SSO(통합인증) 솔루션 제안 여지: SAML 2.0, OAuth 2.0, OpenID Connect 표준 기반 SSO를 요구하며, Red Hat SSO(Keycloak 상용)는 해당 표준을 완벽히 지원 — 국내 파트너사와 협력하여 제안 가능
  • 컨테이너·클라우드 인프라 제안 여지: G-Cloud 기반 시스템 구성을 허용하며, 클라우드 환경에서 OpenShift(OCP) 또는 RHEL 기반 컨테이너 플랫폼 제안을 통해 안정성·보안성 강조 가능
  • Ansible을 활용한 운영 자동화 제안: 36개월의 장기 사업으로 단계별 시스템 배포·운영 자동화 솔루션으로 Ansible Automation Platform 추가 제안 가능
  • RFP 내 Red Hat 제품명 명시 없음 — 높음 판정 근거 없음. 현재 판정은 중간(OS 미지정·제안 여지) 수준.
