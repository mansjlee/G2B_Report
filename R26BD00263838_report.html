사업 개요 및 목적
  • 2009년 구축된 한국음악저작권협회(KOMCA) 정보시스템이 17년 경과로 노후화·거대화됨에 따라, ISP(2023) 결과를 기반으로 전면 차세대 재구축을 추진하는 사업
  • 음악사용자료 대량 처리·AI 매칭, 저작물 등록·징수·분배·정산 전 생애주기의 자동화 및 디지털 전환을 핵심 목표로 함
  • AI Assistant, AI OCR, RAG 기반 지능형 서비스 도입을 통해 반복·수작업 업무를 자동화하고, 근거 기반 업무 지원 체계 마련
  • 컨테이너 기반 클라우드 아키텍처, CI/CD 배포 환경, 국제표준(CISAC, DDEX) 연계 체계를 구축하여 시스템 확장성·안정성 확보
  • 대민 홈페이지와 신탁회원 전용포털을 분리 구축하고, 전자서명 기반 전자계약 체계 도입으로 비대면 서비스 강화

핵심 요구사항
  • [기술·비즈니스 요구사항]
    • 컨테이너 기반 차세대 시스템 아키텍처 구축(ISR-002): 컨테이너 기반 서비스, 로드밸런싱, 자동 자원관리, 오토스케일링
    • CI/CD 파이프라인 구축(ISR-003): 자동 빌드·배포, 롤백, 무중단 배포, 파이프라인 가시성 및 감사추적
    • AI 기반 지능형 서비스(SFR-012/PER-008): RAG 기반 AI Assistant(임직원), AI 챗봇(회원·이용자), AI 매칭(음악사용로그-저작물, 큐시트), AI OCR(비정형 서류 자동 판독), 일 최대 1억 건 로그 처리 성능
    • 클라우드 보안 요구사항(ISR-005): 접근통제, DB접근제어, WAF/IDS/IPS 매니지드 서비스, 데이터 국내 리전 저장 원칙
    • 국제표준 연계(INT-003): CISAC(ISWC, IPI, CWR, CRD, AVI/R), DDEX(DSR, CDM) 기반 대외 데이터 연계
    • 대용량 DB 분리 아키텍처: 단일 Oracle DB에서 OLAP(음악사용로그·분배)/OLTP 특성별 분산처리 구조로 전환
    • 전자서명 기반 전자계약 체계 및 본인인증(휴대전화·민간인증서) 적용
    • 웹 표준(KWCAG 2.2), 멀티브라우저, 무설치 방식 준수
  • [RFP 구매 명시 S/W]
    • 본 RFP는 특정 상용 S/W 품목·수량을 직접 지정하지 않으며, 제안사가 목표 아키텍처에 적합한 솔루션을 선정·제안하는 방식(COR-006: 도입 상용SW·오픈소스 종류·버전·수량·라이선스 조건을 제안사가 명시)
    • 현행 유지보수 중인 S/W(교체 또는 유지 결정은 제안사 재량): ORACLE 19C(AWS RDS), WEBTOB(티맥스), JEUS(티맥스), Jennifer(제니퍼), 검색엔진(와이즈넛), 그룹웨어(더존), Spamout(넷엔씨큐), Miplatform(TOBESOFT), UbiReport(유비디시전), Processbuilder(wizware), EMS(대량메일)
    • 신규 도입 검토 대상(제안사 결정): 벡터DB, 그래프DB, LLM 서빙 환경, AI OCR 솔루션, 전자서명 솔루션, CI/CD 툴, 컨테이너 오케스트레이션 플랫폼, WAF·IDS·IPS 매니지드 보안 솔루션
Red Hat 제안
불가능 요소
  • Red Hat 상용 제품 미명시: RFP 전체에 걸쳐 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 구매·도입 품목으로 단 한 건도 명시되어 있지 않음 → 수요기관 주도 RH 도입 확정 아님
  • 경쟁 WAS·미들웨어 현행 사용: 현행 WEB은 WEBTOB(티맥스), WAS는 JEUS(티맥스)로 운영 중이며, 차세대 전환 시 동일 티맥스 계열 또는 타 Java WAS 유지 가능성 존재 → JBoss EAP 포지셔닝 경쟁 필요
  • Oracle DB 기반 환경: 현행 Oracle SE2(AWS RDS)가 핵심 DBMS로 운영 중이며, 대용량 분산 DB 아키텍처로 전환 시에도 Oracle 계속 사용 가능성 있음 → Red Hat Data Grid 등 제안 시 Oracle 포지션과 충돌
  • 특정 경쟁 제품 명시 없음(양날의 검): Ubuntu, Rocky Linux, VMware 등 직접 경쟁 제품도 명시되지 않았으나, OS·플랫폼이 미확정 상태이므로 타 벤더 제안 시 경쟁 심화 가능
  • AWS 기반 클라우드 환경: 현재 AWS를 클라우드 인프라로 사용 중이며, 차세대도 AWS 기반 유지 가능성이 높음 → Red Hat OpenShift on AWS(ROSA) 등 클라우드 네이티브 연계 전략 필요
Red Hat 제안
가능 요소
  • 컨테이너 기반 아키텍처 의무화(ISR-002): RFP에서 "차세대 시스템은 컨테이너 기반으로 서비스를 제공해야 함"을 필수 요구사항으로 명시 → OpenShift Container Platform(OCP) 제안 최적 포인트. 로드밸런싱, 자동 자원관리, 오토스케일링 모두 OCP 기능으로 충족 가능
  • CI/CD 파이프라인 구축 필수(ISR-003): 지속적 통합·배포, 자동/수동/배치 트리거, 배포 이력·롤백, 무중단 배포, 감사추적 요구 → OpenShift Pipelines(Tekton), OpenShift GitOps(ArgoCD), Ansible Automation Platform 제안 가능
  • 클라우드 Linux OS 미지정(제안 여지): 현행 서버 OS가 'L'(Linux 계열)로만 표기되어 있고 차세대 OS는 명시되지 않음 → RHEL(Red Hat Enterprise Linux) 클라우드 인스턴스 제안 가능. AWS RHEL AMI 또는 ROSA(Red Hat OpenShift Service on AWS) 활용 가능
  • AI/ML 인프라 구축 요구(SFR-012, PER-008): RAG 기반 AI Assistant, AI 챗봇, AI 매칭 엔진, LLM 서빙, 벡터DB, MLOps 체계 구축 요구 → OpenShift AI(RHOAI)를 통한 AI 워크로드 플랫폼, 모델 서빙·모니터링 체계 제안 가능. 일 최대 1억 건 로그 AI 매칭 처리 요구에도 대응 가능
  • 인프라 자동화·형상관리 요구(QUR-002, ISR-003): 배포 자동화, 형상관리 기반 이력관리, 변경사항 신속 반영, 운영 자동화 요구 → Ansible Automation Platform(AAP)을 통한 인프라 프로비저닝·구성관리·배포 자동화 제안 가능
  • 고가용성·이중화·SPOF 제거 요구(PER-004): 애플리케이션·DB·네트워크 주요 구성요소 이중화 및 단일장애점 제거 필수 → OCP의 클러스터 고가용성 아키텍처로 요건 충족 가능
  • 보안 강화 요구(ISR-005, SER 전반): 클라우드 접근통제, DB접근제어, 소프트웨어 개발보안, 컨테이너 보안 요구 → Red Hat Advanced Cluster Security(ACS)를 통한 컨테이너·Kubernetes 보안 제안 가능
  • RFP 내 Red Hat 제품 명시 현황: RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 RFP 내에 명시되어 있지 않음 (커뮤니티 제품 포함 전무)
