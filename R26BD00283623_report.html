건설근로자공제회_건설e음 기능 개발 사업 - 분석 리포트

레드햇 제안 가능성 낮음
S/W 납품 없는 개발용역, JEUS WAS 기존 사용
사업 개요 및 목적
  • 건설근로자공제회가 2026년 1월에 오픈한 건설e음 시스템(통합민원시스템 + 사업관리시스템)을 기반으로 신규 기능을 추가 개발하는 사업 (신규 구축 아님)
  • 산재예방 인센티브: 노동자 안전활동(안전교육, 무사고 출퇴근 등) 완료 시 포인트 적립·지급 기능 마련
  • 신규 생체인증: 기존 지문인식 외 안면인식·장정맥 방식 추가 도입으로 전자카드 부정사용 방지
  • QR코드 출퇴근: 공사예정금액 3억 미만 소규모 현장 대상 모바일 앱 QR코드 출퇴근 방식 도입
  • 교육·평가 관리: 기능등급제 고유 업무(교육과정관리, 수강관리, 평가관리) 전 주기 온라인화
  • AI 경력설계: 기능인의 직종·등급·교육이력 기반 맞춤형 경력 개발 경로 및 교육과정 추천 기능
주요 정보
  • 사업 예산: 923,000,000원 (VAT 포함)
  • 사업 기간: 계약 체결 후 270일 (긴급입찰 사유: '26년 내 기능 구현 완료 필요)
  • 사업 범위: ① 산재예방 인센티브 기능 ② 신규 생체인증(안면인식·장정맥) ③ QR코드 출퇴근 ④ 사업주·노동자 업무편의 기능 ⑤ 교육관리·평가관리 기능 ⑥ AI 경력설계 기능 — 총 86개 요구사항(기능 36, 성능 4, 인터페이스 10, 데이터 5, 테스트 5, 보안 6, 품질 4, 제약 5, 프로젝트관리 6, 프로젝트지원 5)
  • 계약 방법: 제한경쟁입찰(협상에 의한 계약), 중소기업자간 경쟁, 조달청 위탁평가 (기술 90점 + 가격 10점)
  • 주요 일정: 긴급입찰 공고(조달청) → 제안서 평가 → 협상 → 계약 체결 후 M+8개월(270일) 완료, 이후 하자보수 12개월

핵심 요구사항
  • 기술 요구사항 핵심:
    • 기존 건설e음 시스템(통합민원시스템·사업관리시스템) 기반 위에 신규 기능 추가 개발 — 기존 운영 영향 최소화 필수
    • 현행 JEUS MQ(메시지 큐)를 활용하여 생체인증·QR코드 출퇴근 처리 프로세스 구성 (기존 프로세스 유지)
    • 모바일 앱(Android + iOS) 및 웹 표준 기술 준수
    • 기 도입된 UMS 솔루션(푸시 메시지), 배치 솔루션(알림 서비스) 연계 개발
    • Open API(REST 방식), SFTP 방식 연계 지원, 고용노동부 시스템(hrdnet, worknet) 외부 데이터 연계
    • 전자정부 표준프레임워크 적용, 행정안전부 UI/UX 가이드라인 준수
    • 시큐어코딩 의무화, 개인정보보호법 준수, 감리 대응 협조
  • 구매가 명시된 S/W:
    • 본 RFP에 통합발주 또는 상용 S/W 품목이 별도 명시되지 않음
    • H/W 및 S/W 인프라는 발주기관(건설근로자공제회)이 제공하는 것을 원칙으로 함 (RFP 3.7항)
    • 현 보유 자산을 최대 활용하되, 추가 필요 라이센스는 제안사가 제안 가능 (구체적 품목 미지정)
Red Hat 제안
불가능 요소
  • S/W 납품 항목 없음: H/W 및 S/W 인프라 일체를 발주기관이 제공하며, 별도 상용 S/W 구매 품목이 RFP에 전혀 명시되지 않음. 본 사업은 실질적으로 순수 소프트웨어 개발 용역에 해당
  • 경쟁 미들웨어(JEUS MQ) 명시 사용: RFP SFR-012, SFR-019, SFR-020 등에서 현재 상용 WAS인 JEUS(TmaxSoft)의 MQ(메시지 큐)를 활용한 처리 방식이 요구사항으로 확정됨 → JBoss AMQ/Red Hat 미들웨어 제안 불가
  • Red Hat 상용 제품명 전혀 미명시: RHEL, OpenShift, Ansible, JBoss EAP, AAP, Quay, Satellite 등 Red Hat 상용 제품·동의어가 RFP 본문·과업지시서·구매 목록 어디에도 등장하지 않음
  • 입찰 구조상 Red Hat 직접 참여 불가: 중소기업자간 제한경쟁입찰(소프트웨어사업자 컴퓨터관련서비스업 등록 필수), 총사업금액 20억 원 미만 중소SW사업자 전용 입찰로 제한됨
Red Hat 제안
가능 요소
  • Linux 서버 OS 옵션 포함: 기술적용계획표 "플랫폼 및 기반구조" 분야에 서버용 개방형 OS로 Linux ○가 명시됨 — 발주기관 인프라 교체 또는 확장 시 RHEL 제안 여지가 이론적으로 존재하나, 본 사업 범위에 포함되지 않음
  • 제안사 자율 S/W 제안 조항: "제안사는 배정된 사업 예산 범위 내에서 최적의 성능 및 안정성을 보장하는 S/W 및 H/W 구성을 자율적으로 제안할 수 있다"는 조항이 있으나, 발주기관이 인프라를 제공하는 원칙과 상충되며 실질적 도입 가능성은 극히 낮음
  • 종합 판단: Red Hat 상용 제품이 단 하나도 명시되지 않았고, 기존 JEUS 인프라가 확정 사용되며, 인프라는 발주기관 제공 원칙으로 사실상 Red Hat 제품 제안·납품 기회 없음
