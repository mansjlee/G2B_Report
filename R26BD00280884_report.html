Red Hat 제안
불가능 요소
  • S/W 납품·구독 항목 전무: 본 사업은 보안관제 전문인력의 상주 위탁운영 서비스 용역으로, RFP 전체에 걸쳐 S/W 제품 구매·도입·납품 관련 항목이 일절 존재하지 않음
  • Red Hat 제품 미언급: RHEL, OpenShift, Ansible, JBoss 등 Red Hat 상용 제품명이 RFP 어디에도 명시되지 않음
  • 경쟁 제품도 미언급: Ubuntu, VMware, Rocky Linux, Oracle Linux 등 경쟁 OS/플랫폼도 명시 없으나, 기존 운영 중인 보안관제 시스템(ESM, TMS, SOAR 등)을 그대로 유지·운영하는 구조로 신규 플랫폼 도입 여지 없음
  • 하도급·재하도급 불가: Red Hat 파트너가 하도급 형태로 S/W를 공급하는 구조 자체가 계약 조건상 불허
  • 인력 용역 중심 평가 구조: 기술평가 항목이 보안관제 방안, 위협관리, 인력운영, 사업관리 등 순수 서비스 역량 평가로 구성되어 있어 S/W 제품 제안 자체가 평가 구조에 맞지 않음
  • 보안관제 전문기업 한정 입찰: 업종코드 6526 보안관제 전문기업만 참여 가능하여 Red Hat이 직접 입찰하거나 S/W 납품 형태로 참여하는 구조 불가
Red Hat 제안
가능 요소
  • 직접 제안 가능 요소 없음: RFP에 Red Hat 상용 제품(RHEL, OpenShift, Ansible, JBoss EAP 등)이 품목으로 명시되지 않았으며, S/W 구매 자체가 없는 순수 용역 사업이므로 Red Hat 제품을 직접 제안할 기회가 없음
  • 간접 영향 가능성(매우 낮음): 관제 대상 19개 기관의 정보시스템 운영환경에 RHEL 등이 사용 중일 가능성이 있으나, 본 사업의 과업 범위는 기존 시스템 운영·유지관리이며 신규 플랫폼 도입을 수반하지 않음
  • 클라우드 보안 대응방안 수립 과업: 민간 클라우드 활용 기관의 보안관제 전략 수립이 요구되나, 이는 컨설팅 성격의 문서 산출물이며 Red Hat OpenShift나 RHEL 등의 실제 구매로 이어지지 않음
  • RFP 내 Red Hat 제품명 명시 없음: 판정 규칙 상 '높음' 또는 '중간' 판정의 근거가 되는 Red Hat 상용 제품명, 커뮤니티 제품명, Linux/컨테이너/Kubernetes 도입 관련 요구사항이 전혀 없음
