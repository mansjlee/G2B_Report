국가과학기술연구회_과학연구자 대상 AI운영환경(AI-OS) 시범 서비스 개발 - 분석 리포트

레드햇 제안 가능성 중간
Kubernetes·컨테이너 기반 명확한 제안 여지
사업 개요 및 목적
  • 과학기술 분야 23개 정부출연연구기관(출연연)을 대상으로 AI 운영환경(AI-OS)의 표준규격을 확정하고 핵심 기능을 개발하여 시범 서비스를 개시·검증하는 사업
  • 인프라(실행환경)부터 에이전트(연구지원 에이전트)까지 관통하는 계층형 표준 체계를 구축하여 기관 간 호환성 및 상호운용성 확보
  • 국가 망 보안체계(N2SF) O등급 기준 설계 및 S·C등급 확장 가능 구조를 확보하여 안전한 연구 AI 활용 환경 구현
  • 데이터 등록→자산화→에이전트 분석→리포트 산출→자산 환류까지 전 과정 관통하는 연구 AI 운영체계 시범 운영
  • 클라우드(CSP 조달·운영) 구간과 발주기관 별도 확보 인프라 구간의 이원(Dual) 구조로 각 500명씩 시범 사용자 1,000명 수용

  • 사업 기간: 계약체결일로부터 2개월 (2026년 10월 ~ 2026년 12월 예정)
  • 사업 범위:
    • ① 실행환경: Kubernetes 기반 컨테이너 오케스트레이션, GPU 자원 풀 구성·할당, 실행환경 격리
    • ② 모델운영: 표준 워크로드 실행(Job API), 모델 레지스트리·버전관리, LLM 내부 서빙, 멀티모델 라우팅·외부 모델 API 연계
    • ③ 연구자산 관리: 카탈로그·메타데이터 표준, 계보(Lineage) 관리, 하이브리드 검색, 데이터레이크 구축
    • ④ 연구지원 에이전트: 공통 Agent Runtime, MCP 표준 도구 연동, HITL 승인 게이트, 연구지원 앱 3종(연구동향분석/실험가설·설계·검증/데이터분석)
    • ⑤ 공통관리·보안: 통합 인증(SSO)·RBAC, 감사로그, 데이터 등급 분류·반출 통제, N2SF 보안통제 11종 반영
    • 클라우드 구간 인프라 조달·운영, KISTI 슈퍼컴퓨팅 GPU 자원 연계, 시범 서비스 개시 및 이관
  • 주요 일정:
    • 착수 +1개월(M1): 요구사항 확정, 기능 영역별 표준규격·보안 아키텍처 확정, 핵심기능 개발 착수
    • 착수 +2개월(M2): 통합시나리오 시험, 시범 서비스 개시, 운영 이관·사업 종료
    • 계약방식: 협상에 의한 계약 / 중소기업자 제한경쟁 / 단독응찰 원칙

  • 상용 S/W 납품 항목 없음: 통합발주·상용SW 구매 목록에 Red Hat 제품 포함 없음. 오픈소스 기반 자체 구축이 전제이며 특정 상용 제품 납품 구조가 아님
  • Red Hat 상용 제품명 미명시: RFP 전문에 RHEL, OpenShift(OCP), Ansible, JBoss EAP, Satellite, Quay 등 Red Hat 상용 제품명이 단 한 건도 언급되지 않음
  • 중소기업자 제한경쟁: 본 사업은 중소기업자만 입찰 가능(사업금액 758,910,000원, 40억 미만). Red Hat Korea 직접 입찰 불가. 단독응찰 원칙으로 공동수급체 구성도 불허하여 Red Hat이 주도하는 제안 구조 형성 어려움
  • CSP 종속 배제 및 오픈소스 우선 원칙: "특정 상용 제품·클라우드·AI 모델에 종속되지 않도록 어댑터 계층 적용"(COR-ARC-STD-01), "관리형 서비스에 종속되지 않는 오픈소스 표준 기반 구성 원칙"이 제약사항으로 명시되어 특정 상용 플랫폼 도입이 구조적으로 제한됨
  • 경쟁 제품 명시 없음: VMware, Ubuntu, Oracle Linux 등 경쟁 제품도 명시되지 않아 대체 기회는 있으나, 오픈소스 Kubernetes 직접 구축을 기본 전제로 함
Red Hat 제안
가능 요소
  • [OpenShift Container Platform (OCP) 제안 기회]: SFR-INF-VRT-01에서 "Kubernetes 또는 동등 이상의 컨테이너 오케스트레이션 기반 표준 실행환경 구축" 요구. OpenShift는 Kubernetes 표준 기반이며 엔터프라이즈 보안·운영 기능 강점. "이식 가능한 구조"·"오픈소스 표준 기반" 요건과 정합
  • [Quay / OpenShift Image Registry 제안 기회]: 컨테이너 이미지 레지스트리 설계·구성(SFR-INF-VRT-01), 이미지 서명·무결성 검증, 취약점 스캔(SFR-INF-VRT-05) 요구. Quay의 이미지 서명·스캔·미러링 기능이 폐쇄망 운영 요건에 부합
  • [Ansible Automation Platform 제안 기회]: CI/CD 파이프라인 자동화(SFR-INF-VRT-01), IaC 기반 클러스터 구성·관리(ECR-001), 인프라 구간 탑재·이관 자동화(ECR-002) 요구. Ansible의 에이전트리스 자동화 및 IaC 연계 강점
  • [Red Hat SSO (Keycloak 상용) 제안 기회]: OAuth2/OIDC·SAML 기반 통합 인증(SSO), 계정 생명주기 관리, MFA, 에이전트 식별(Agent Identity) 관리(SER-GOV-IAM-01) 요구. 특정 CSP 관리형 인증 서비스 종속 배제 원칙에서 표준 기반 Red Hat SSO 경쟁력 확보 가능
  • [RHEL 인프라 제안 기회]: 인프라 구간 별도 발주 서버 탑재(ECR-002), 클라우드 구간과 동일 형상 배포 구조 요구. RHEL 기반 표준화된 OS 환경은 컨테이너 이미지 일관성 및 보안 요건 충족에 유리
  • [OpenShift Pipelines / GitOps 제안 기회]: CI/CD 파이프라인, 롤링 업데이트·자동 롤백(SFR-INF-VRT-01), 배포 이력 관리 요구. Tekton 기반 OpenShift Pipelines 및 ArgoCD 기반 GitOps가 IaC·형상관리 요건에 정합
  • [RFP 내 Red Hat(동의어) 제품명 명시 현황]: 없음 — RHEL, OpenShift, OCP, Ansible, JBoss, EAP 등 Red Hat 상용 제품명이 RFP 전문에 전혀 명시되지 않음
  • [총평]: 직접 명시된 Red Hat 제품은 없으나, Kubernetes·컨테이너·CI/CD·IAM·이미지 레지스트리 등 Red Hat 핵심 기술 스택이 광범위하게 적용 가능한 구조. 중소기업 입찰사 대상 Red Hat 파트너 영업(파트너를 통한 솔루션 제안)이 현실적인 접근 전략
