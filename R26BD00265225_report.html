  • S/W 미포함 여부: 해당 없음. 통합발주 S/W 품목 다수 포함된 복합 사업

  • OpenShift 미명시: K8s(쿠버네티스) 기반으로만 언급. OpenShift가 직접 명시되지 않아 제안 시 추가 근거 필요
  • Ansible 미명시: RFP 내 Ansible 또는 자동화 플랫폼 관련 직접 언급 없음
  • 특정 기술 종속 최소화 원칙: COR-004에 "부득이한 경우를 제외하고는 특정 기술에 종속되지 않는 개방형 기술로 구현" 명시 → 특정 벤더 의존도 최소화 요건 있음, 제안 시 오픈스탠더드 준수 근거 제시 필요
  • 가상화 솔루션 OEM/ODM 제외: INR-DTL-003에 "원활한 유지관리를 위해 OEM/ODM 제외" 조항 존재 (가상화 솔루션 한정)
  • 기존 보안 솔루션 연계 조건: SSO(INTECH NexessClient), 서버 접근제어(HIWARE TAM), 백업(Veeam Data Platform) 등 기존 솔루션과 연계·호환 조건이 있어 신규 RH 보안 제품 진입 제약 가능

가능 요소
  • [RFP 명시 Red Hat 제품]
    • Linux RedHat 9.x: 기존 공사 보유 서버(HPE DL380a Gen12) 2식의 OS로 명시 → RHEL 상용 제품이 현재 운영 중임을 확인
  • [RHEL 신규 납품 기회]
    • 신규 서버 납품 조건(INR-DTL-001): "정품 라이선스가 포함된 최신 버전의 가상화 운영체제(64bit), 상용 Linux / 3년 워런티 제공" 명시 → RHEL은 대표적 상용 Linux로 해당 요건 충족 가능
    • 신규 HCI 서버 다수(내부망 일반 4식, GPU 1식, 개발망 일반 3식, GPU 2식) 납품 대상 → RHEL 라이선스 동반 제안 가능
    • INR-007(상용 S/W 도입 일반): "OS 및 상용 S/W는 안정성이 보장된 최신 버전으로 제안" 명시 → RHEL은 상용 OS로 해당됨
  • [OpenShift 제안 여지]
    • K8s 기반 GPU 클러스터, 컨테이너 환경(Docker 이미지), Ingress Controller, L4 Load Balancer 등 OpenShift Container Platform 적용 가능한 기술 요구사항 다수
    • 생성형 AI 관리 솔루션 내 K8s, Kafka, Elastic Search, Redis 등 OpenShift 생태계와 정합성 높은 구성 요소 명시
    • OpenShift AI(RHEL AI) 기반 LLMOps, 모델 서빙(vLLM 통합), Multi-LLM 운영 제안 검토 가능
  • [기존 RHEL 환경 호환성 강점]
    • INR-009(호환성 및 상호운영성): 기존 시스템과 안정성 보장 제품으로 구축 요건 → 기존 RHEL 9.x 환경과 동일 플랫폼 유지가 호환성 측면에서 유리
  • [ML/DL 환경 RHEL 적용 가능성]
    • FUR-007(ML·DL 구동환경): TensorFlow, PyTorch, Scikit-learn 등 주요 ML/DL 프레임워크 및 CUDA 환경이 적용된 도커 이미지 및 컨테이너 기반 환경 요구 → RHEL 기반 컨테이너 환경 구성 가능
  • [Ansible 잠재 기회]
