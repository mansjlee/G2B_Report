강원대학교_통합 강원대학교 ICT 인프라 구축 사업(2단계) - 분석 리포트

레드햇 제안 가능성 중간
가상화·OS미지정 제안여지
사업 개요 및 목적
  • 4개 캠퍼스 통합에 따라 정보시스템을 단일 운영환경에서 관리하기 위한 통합 ICT 인프라(서버·스토리지·가상화·백업)를 구축하는 2단계 사업이다.
  • 2027년 9월 부분 오픈 예정인 통합정보시스템의 개발·운영 자원을 2027년 3월 개발 착수 전에 확보하는 것이 핵심 목표이다.
  • 보유 서버와 신규 서버를 하나의 가상화 클러스터로 통합해 중복 투자와 상용 가상화 라이선스 부담을 줄이고, 캠퍼스별로 분산된 백업을 단일 체계로 통합한다.
  • 춘천(주 백업)·강릉(Warm DR 복구 거점)·삼척(보관) 역할 분담으로 장애·재해 시 핵심 서비스 재개 기반을 마련한다.
주요 정보
  • 사업 예산: 2,571,397,400원 (VAT 포함). 대기업 참여제한 사업(20억 원 이상 40억 원 미만 SW사업). 하도급 불허. 공동수급(공동이행, 5개 이내) 허용.
  • 사업 기간: 계약일로부터 2027.2.19.까지. 구축 완료 후 최소 1개월 이상 시범운영. 무상 하자보수 검수완료일로부터 12개월(개별 물품 보증이 더 길면 해당 기간). 서버·스토리지 무상하자 3년, 가상화 3년 기술지원, 백업 SW 5년 유지보수.
  • 사업 범위: 신규 가상화 호스트 서버 6대 + 보유 서버 10대(합계 16대 클러스터), All Flash 스토리지 1식(가용 180TB 이상), 통합 백업 솔루션 1식(200노드), 백업 서버 2대, 백업 저장장치 2식(춘천·강릉 각 126TB 이상), 기존 VM 이전(200대 이상), 강릉 Warm DR 구성. PaaS·DBMS·DB 전용장비는 별도 도입이며 본 사업은 네트워크·스토리지·백업 연계 및 백업 모듈 공급.
  • 주요 일정: 입찰방식은 제한경쟁·협상에 의한 계약(기술 90% / 가격 10%). 추진 일정은 사업계획·입찰공고(M1) → 협상·계약(M2) → 장비 도입·구축(M2~M3) → 운영테스트·안정화(M4) → 사업완료·검수(M4) → 모니터링·유지관리(M4+1). 인프라는 2027.3 개발 착수 전 확보, 통합정보시스템은 2027.9 부분 오픈. 제안요청 설명회는 미실시. 제출기한은 입찰공고문 참조.

핵심 요구사항
  • 신규 서버 6대(2소켓×32Core 이상, 메모리 1,024GB 이상 등)와 보유 서버 10대를 단일 가상화 클러스터(16노드, 소켓 32·코어 736)로 구성하고, 웹 기반 통합 관리·HA·라이브 마이그레이션·스냅샷·RBAC·REST API/CLI·자동화 도구 연동을 제공한다. 가상화 제품은 보안기능확인서 또는 CC인증 필수.
  • 기존 가상화 환경(이전 기간 중 VMware 포함)의 VM을 신규 플랫폼으로 이전(OVF/OVA 또는 제조사 변환 도구). 이관 대상 VM 총 200대 이상.
  • All Flash(NVMe) 스토리지 1식(Usable 180TB 이상, FC 32G)을 가상화 공용 저장소로 구성하고, 가상화 멀티패스·스냅샷 및 별도 PaaS 영구볼륨(CSI) 연동을 지원한다.
  • 통합 백업(물리·VM 합계 200대 + PaaS 4노드)으로 가상서버·DB(Oracle, MySQL 등)·컨테이너 워크로드·PV·파일을 단일 콘솔에서 보호하고, 춘천→강릉 복제 및 복구시험, 불변저장·랜섬웨어 탐지, GS 또는 CC인증을 충족한다.
  • 강릉캠퍼스 Warm DR: 재해복구망(10G) 복제, 보유 서버에 가상화·PaaS·통신·보안 환경을 구성해 서비스 단위 복구. 검수 전 복구시험 필수.
  • 서비스 특성에 따라 물리서버·가상서버·PaaS(컨테이너) 적용 구분 방안을 제시하고, 별도 도입 PaaS·DBMS와 네트워크·스토리지·백업을 연계한다.
  • 상용 H/W·S/W 일괄 공급·설치, 제조사 공급증명서·기술지원 확약서(계약 후 14일 이내), 정품·지식재산권 명확화, 대기업 참여제한·하도급 불허.
  • 통합발주 구매 명시 S/W(조달쇼핑몰 직접구매 아님, 품목명·수량 그대로):
    • 가상화 솔루션(하이퍼바이저 및 웹 기반 통합 관리도구) 16 (원주캠퍼스용 1대분 포함, CPU 소켓·코어 사용권 및 3년 기술지원 구독 포함 / 소켓 32개·코어 736개·노드 16대 이상)
    • 서버 OS 라이선스 10
    • 백업 솔루션 1 (200노드, 컨테이너 플랫폼(PaaS) 4노드 백업·복구 라이선스·모듈 포함, 전 품목 5년 유지보수·기술지원)
    • Microsoft Windows Server 2025 Standard 또는 Datacenter 10식
  • 참고: 「기존 가상서버 이전 작업 16」은 이관 작업이지 S/W 제품이 아님. 백업 서버 2대·백업 저장장치 2식·All Flash 스토리지 1식은 H/W. 품목명·수량은 특정 제조사 지정이 아니며 최종 규격은 ECR-03~08을 따른다고 명시.
Red Hat 제안
불가능 요소
  • S/W 공급이 없는 순수 용역은 아니다. 다만 RFP·도입내역·ECR 어디에도 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명·수량이 품목으로 명시되지 않았다.
  • 경쟁·대체 제품: 서버 OS는 Microsoft Windows Server 2025 Standard 또는 Datacenter 10식이 명시되어 RHEL을 해당 10식의 대체 품목으로 넣기 어렵다. 기존 가상화는 이전 기간 중 VMware가 운영 중이며, 백업 솔루션은 기존 VMware VM 백업·복구를 지원해야 한다. Ubuntu·Rocky·Oracle Linux·CentOS·Fedora·WildFly는 명시되지 않았다.
  • 추진 목적에 「상용 가상화 라이선스 부담 축소」가 있어, 구독 비용이 높은 상용 가상화(OpenShift Virtualization 등)만으로 가격 경쟁력을 입증하기 어려울 수 있다.
  • 가상화 제품은 보안기능확인서 또는 CC인증(인증 범위에 제품명·버전)이 필수이고, 백업은 GS 또는 CC인증이 필수이다. 인증 미보유 구성은 제안 탈락 위험이 크다.
  • PaaS(컨테이너 플랫폼)는 별도 사업으로 구축되며 본 사업은 백업 모듈 공급·연동에 한정된다. OpenShift를 본 건 통합발주 품목으로 직접 납품할 근거는 없다.
  • 대기업인 SW사업자 입찰 참여 제한, 하도급 불허로 Red Hat 직접 입찰·하청 납품 구조는 어렵다. 중소·중견 SI 컨소시엄 제안 내 제품 탑재 방식이 현실적이다.
Red Hat 제안
가능 요소
  • 가상화 솔루션(16노드)은 제조사·구현 방식 제한이 없고 KVM 계열 하이퍼바이저+통합 관리도구로 제안할 수 있다. 기존 VMware VM 200대 이상 이전·윈백 시나리오에 Red Hat OpenShift Virtualization 또는 RHEL 기반 KVM 스택을 SI 제안에 포함할 여지가 있다.
  • 호스트/게스트 OS 중 Windows 10식 이외 구간(가상화 하이퍼바이저 기반 OS, 백업 서버 OS(ECR-06, 솔루션 지원 OS), 리눅스 물리서버)에 RHEL 구독 제안이 가능하다. 백업 대상에 윈도우·리눅스 물리서버가 명시되어 있다.
  • 별도 도입 PaaS 4노드·CSI 영구볼륨·컨테이너 백업 연동, 물리·VM·PaaS 적용 구분 방안은 OpenShift와 정합성이 높다. 차기 PaaS 사업 선점·인프라 정합 설계를 본 건 제안 차별화로 활용할 수 있다.
  • 가상화 관리 REST API·CLI·외부 자동화 도구 연동, 클러스터 구성 동기화·순차 업그레이드, 운영 표준화 요구는 Ansible Automation Platform 제안과 맞는다.
  • 기술적용계획표에 서버용 Linux, IaaS·PaaS, 가상화관리제품(보안기능확인서)이 포함되어 RHEL·OpenShift 계열 아키텍처 설명이 가능하다.
  • RFP에 나온 Red Hat(또는 동의어) 제품명·수량: 없음. (RHEL / Red Hat Enterprise Linux / OpenShift / OCP / Ansible / AAP / JBoss / EAP / Satellite 등 상용 제품명·수량 미기재)
