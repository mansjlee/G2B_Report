Red Hat 제안
불가능 요소
  • Red Hat 상용 제품명 미명시: RFP 전문에 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 단 한 건도 명시되지 않음
  • 시스템SW 구성도 비공개: 국가정보자원관리원 입주 HW 및 시스템SW 구성도·제품명은 "보안관계 상 미표기"로 기술 스택 전체가 비공개 상태 → 기존 Red Hat 채택 여부 파악 불가
  • Kubernetes 노드 OS는 MSP 영역: Kubernetes 클러스터 및 노드 OS 유지관리는 MSP가 수행하는 것으로 명시되어 수주자(제안자)의 적용 범위 외
  • 특정 Linux 배포판 지정 없음 (양면적): 특정 Linux 배포판을 지정하지 않아 RHEL 제안이 가능하나, 반대로 이미 다른 배포판이 운영 중일 가능성도 있음
  • SW 납품 직접 수행 아님: 상용SW 118종 616식은 기존 도입분의 유지관리(라이선스 갱신·유지) 위주이며, Red Hat 제품이 목록에 포함되었는지 제품명이 비공개로 확인 불가
  • 경쟁 OS 환경 병존: UNIX, Windows Server, Linux 등 이기종 OS 환경이 혼재하며, 특정 배포판 교체·전환 사업이 아님

가능 요소
  • 컨테이너·Kubernetes 환경 존재: MPR-20에서 컨테이너 이미지 내 Linux 기반 OS 패키지 구성·버전 관리가 수주자 수행 범위로 명시 → RHEL 기반 컨테이너 이미지 또는 UBI(Universal Base Image) 활용 제안 가능
  • Kubernetes 플랫폼 배포판 미지정: 컨테이너 플랫폼이 "Kubernetes(K8S)"로만 표기되며 특정 배포판이 지정되지 않아 OpenShift(OCP) 제안 여지 존재
  • CI/CD·DevSecOps 환경: MPR-29, QUR-01에서 CI/CD 파이프라인 운영관리, SonarQube·Trivy·Polaris 기반 DevSecOps 환경 운영 명시 → Ansible Automation Platform(AAP)을 활용한 자동화 파이프라인, OpenShift Pipelines/GitOps 제안 가능
  • 클라우드 네이티브 전환 진행 중: 클라우드 네이티브 전환 1·2차 사업이 진행 중이며, PaaS 환경 구축이 포함 → OpenShift 기반 PaaS 플랫폼 제안 가능
  • 오픈소스 활용 허용: MPR-19에서 공개SW(오픈소스) 포함 및 보안취약점·버그 유지관리 요구 → Red Hat이 지원하는 오픈소스 기반 기술 스택(Spring Boot, Quarkus 등) 활용 제안 가능
  • 대규모 시스템 운영 환경: 322개 기관 137개 시스템 연계, A1 등급 대용량 공공 포털 → 엔터프라이즈급 RHEL, OpenShift, Ansible 솔루션의 강점 부각 가능
  • 가상화 관리 환경: VM·하이퍼바이저가 SLA 관리 대상으로 명시, 가상화관리제품이 보안기능 확인서 필수 제품군 포함 → RHEV(Red Hat Virtualization) 또는 RHEL 기반 가상화 환경 제안 검토 가능
  • RFP 내 Red Hat 명시 제품: 없음 (제품명 비공개로 기존 채택 여부 미확인)
