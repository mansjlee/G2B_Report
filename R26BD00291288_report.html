한국산업기술기획평가원_균형발전종합정보시스템(NABIS) 인프라 고도화 및 통계서비스 전환 사업 - 분석 리포트

레드햇 제안 가능성 중간
컨테이너·K8s 제안여지, 클라우드 OS 미지정
사업 개요 및 목적
  • 한국산업기술기획평가원(KEIT)이 운영 중인 균형발전종합정보시스템(NABIS)의 성능 노후화를 개선하고, 클라우드 우선 정책(디지털플랫폼정부 실현계획, '23.4월)에 부합하는 인프라 고도화 및 클라우드 전환을 추진하는 사업
  • HCI(Hyper-Converged Infrastructure) 기반 가상화 인프라를 신규 도입하여 시스템 자원의 효율적 운영 기반 마련
  • 외부에서 운영 중인 균형발전현황판을 내부로 이관·통합하고, 통계 데이터를 민간 클라우드(외부망)로 전환하여 보안 강화 및 공공 서비스 고도화
  • 오픈소스 기반 통계 시각화 서비스 도입을 통해 기존 상용 BI 솔루션 의존도 탈피 및 데이터 접근성·활용도 향상
  • 차년도(2단계) 클라우드 전환 사업의 상세설계 및 제안요청서 작성까지 포함한 단계적 전환 기반 수립

핵심 요구사항
  • [기술 요구사항]
    • HCI 가상화 인프라: 국산 HCI SW (GS인증 1등급, 국정원 보안기능확인서 취득 필수), 하이퍼바이저 기반 가상화, 쿠버네티스 클러스터 자동배포·로드밸런싱, V2V 이관 도구, VM 자동복구(Self-Healing) 포함
    • 민간 클라우드: CSAP 인증 국내 CSP 사용, 16vCPU/64GB MEM/500GB 스토리지 이상, CI/CD 파이프라인 구성, 컨테이너 기반 배포
    • 구독형 DBMS: CSAP 인증 CSP 마켓플레이스 제공 국산 관계형 DBMS, 국정원 보안기능확인서 또는 CC인증 취득, 16vCPU 이상
    • 통계 시각화 모듈: 오픈소스(Apache/MIT/BSD/EPL/LGPL) 기반, 상용 BI 솔루션 100% 대체, 토큰 기반 임베딩, 역할 기반 접근제어
    • 성능: 동시 접속 Peak 100명 환경에서 통계 차트 렌더링 3초 이내
  • [구매 명시 S/W (통합발주 포함)]
    • HCI SW (가상화 하이퍼바이저 소프트웨어 및 라이선스): 국산 솔루션, GS인증 1등급, 국정원 보안기능확인서 취득 제품 — HCI Node 3대에 대한 SW 라이선스 포함
    • Node 연결용 스위치 HW: 10Gbps SFP+ 24Port 이상, 전원 이중화 — 2대
    • HCI Node HW (서버): 16Core×2 CPU/256GB MEM/SSD 3.84TB×8 이상 — 3대
    • 구독형 DBMS: 국산 관계형 DBMS, CSAP CSP 마켓플레이스 제공, 16vCPU 이상 — 수량 미명시 (스토리지는 현행 용량 + 3년 증가분 기준 산정)
    • 민간 클라우드 서비스 구독 (OS/WAS/시각화 모듈 실행환경 포함): CSAP 인증 CSP 사용, 16vCPU/64GB MEM/500GB — 수량 미명시 (사업기간+안정화 최소 3개월 제안사 부담)
    • 오픈소스 시각화·차트·리포트 모듈: 무료 오픈소스 라이선스 기반, 별도 구매비용 없음 — 수량 미명시
Red Hat 제안
불가능 요소
  • [HCI SW 국산 의무화]: ECR-001 HCI SW 규격에 "정부 클라우드 전환 정책 부합 및 원활한 기술지원을 위해 국산 솔루션일 것" 명시 → Red Hat은 외산 제품이므로 HCI SW 영역 제안 불가. 또한 GS인증 1등급, 국정원 보안기능확인서 취득 필수 조건이 적용됨
  • [구독형 DBMS 국산 의무화]: CTR-003에서 "국산 관계형 DBMS" 명시 → Red Hat의 데이터베이스 관련 제품 제안 불가
  • [시각화 모듈 오픈소스 한정]: SFR-005에서 "라이선스 비용이 없는 오픈소스 라이선스(Apache, MIT, BSD, EPL, LGPL 등) 기반이어야 함" 명시 → 상용 Red Hat 제품(Quay, Data Grid 등) 제안 불가
  • [컨테이너/Kubernetes 국산 HCI 내장]: HCI 요구사항에 "컨테이너 기반 애플리케이션을 위해 쿠버네티스 클러스터를 자동으로 배포"하는 기능이 포함됨 → 국산 HCI가 컨테이너 플랫폼까지 담당하므로 OpenShift 별도 제안 여지 축소
  • [S/W 납품 범위 제한]: 주요 SW는 ①국산 HCI SW ②국산 DBMS ③무료 오픈소스 시각화 모듈로 한정되어 있으며, 그 외 상용 S/W 도입 항목이 별도로 존재하지 않음
Red Hat 제안
가능 요소
  • [클라우드 VM OS — RHEL 제안 여지]: CTR-001 클라우드 서비스 환경 구성에서 "시스템 SW(OS, WAS, 시각화 모듈 실행환경)가 탑재된 가상자원"을 구성하도록 명시하고 있으나, OS를 특정 제품으로 지정하지 않음. 민간 클라우드(CSAP 인증 CSP) 위에서 구동되는 VM OS로 RHEL 제안 가능. 단, 국산 OS 선호 여지 주의 필요
  • [WAS 실행환경 — JBoss EAP 제안 여지]: "OS, WAS, 시각화 모듈 실행환경"이 필요하다고 명시되어 있으나 WAS 제품을 특정하지 않음. 현행 NABIS의 Java 기반 응용프로그램 클라우드 이관 과정에서 JBoss EAP 제안 가능
  • [CI/CD 파이프라인 — Ansible/OpenShift 제안 여지]: SFR-001에서 "소스 형상관리, 빌드·테스트·배포를 자동화하는 CI/CD 파이프라인을 클라우드 환경에 구성"하도록 요구. Ansible Automation Platform(AAP) 또는 OpenShift Pipelines(Tekton 기반) 제안 가능성 존재
  • [컨테이너 기반 배포 환경]: SFR-001, SFR-002에서 "컨테이너 기반 실행환경으로 전환", SFR-005에서 "컨테이너 기반으로 민간 클라우드 환경에 배포" 요구 → 민간 클라우드 영역 컨테이너 런타임(Podman) 또는 OpenShift 제안 여지
  • [RFP 내 Red Hat 제품명 명시]: 없음 (Red Hat, RHEL, OpenShift, Ansible, JBoss 등 일체 미언급)
