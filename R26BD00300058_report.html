불가능 요소
  • 신규 S/W 납품·구독 항목 없음: 본 사업은 순수 운영·유지관리 용역으로, 신규 S/W(상용 라이선스 포함) 도입·납품·구독 갱신 등의 별도 구매 품목이 RFP에 명시되어 있지 않음
  • Red Hat 상용 제품명 미명시: RFP 전체(현행 시스템 구성, 유지관리 대상 S/W 목록, 솔루션 목록 등) 어디에도 RHEL, Red Hat Enterprise Linux, OpenShift, Ansible, JBoss EAP, Satellite 등 Red Hat 상용 제품명이 정확히 기재되어 있지 않음
  • 경쟁·대체 제품 직접 명시 없음: Ubuntu, Rocky Linux, Oracle Linux, VMware 등 경쟁 제품도 명시되지 않아 대체 불가 확정 상황은 아니나, Red Hat 상용 제품 도입을 명시적으로 요구하지 않음
  • 운영 중인 솔루션 대부분 타사 제품: AhnLab EPP, 노머신(NX), Zabbix, Elasticsearch, Redmine 등 오픈소스 및 타사 솔루션이 현행 운영 환경의 주축을 이루고 있음
  • 중소기업 제한 입찰: 총 사업금액 20억원 미만으로 대기업·중견기업 입찰 불가 (Red Hat 직접 참여 불가, SI 파트너를 통한 간접 제안만 가능)
  • 하도급 불허: 본 사업은 하도급을 명시적으로 불허하여 Red Hat이 하도급 형태로 참여하는 것도 불가
Red Hat 제안
가능 요소
  • 대규모 Linux 서버 운영 환경: 유지관리 72대 + 운영관리 235대 등 300대 이상의 서버가 운영 중이며, KSTAR 제어시스템에서도 다수의 서버(EPICS IOC 서버 100대 등)가 Linux 기반으로 추정됨. OS 종류가 명시되지 않아 RHEL 제안 여지 존재
  • Yum Repository 명시: KSTAR 제어시스템 유지관리 대상 중 "Yum Repository" (1대) 가 명시되어 있어, Red Hat 계열(RHEL/CentOS 등) Linux가 운영 중임을 강하게 시사함. 다만 정확한 제품명(RHEL vs CentOS 등)은 불명확하여 중간 수준의 판정 근거로 적용
  • EPICS 기반 제어시스템 — Linux 연계 필수: KSTAR 제어시스템은 EPICS, MDSplus, CS-Studio, CODAC Core System(Linux 기반) 등을 운영하며, 이들은 대부분 RHEL 계열 Linux를 기반 OS로 사용하는 것이 일반적임. 향후 OS 갱신·교체 시 RHEL 제안 가능
  • Ansible 활용 가능성: 300대 이상 서버의 보안 패치 자동화(반기별 OS 보안 패치 적용), 형상관리, 환경설정 자동화 요구사항에 대해 Ansible Automation Platform(AAP) 제안 여지 있음
  • 컨테이너/가상화 환경: 운영관리 대상에 VMHost 4대, 통합가상화시스템 12대, KVM 기반 서버(cvp-kvm1~3, XXHCI 4대) 등이 포함되어 있어 컨테이너·가상화 환경의 현대화 제안 가능
  • RFP에 명시된 Red Hat(또는 동의어) 제품명·수량: 없음 (상용 Red Hat 제품명은 RFP 어디에도 명시되지 않음). 단, Yum Repository 운영은 RHEL 계열 사용의 간접 증거로 활용 가능
  • 영업 접근 전략: 현 사업은 유지관리 용역이나, 본 사업 수행 업체(SI 파트너)를 통해 운영 중인 Linux OS 현황 파악 후 RHEL 구독 갱신·전환 기회를 모색하거나, 차년도 인프라 도입 사업 발굴을 위한 고객 접점 확보에 활용 가능
