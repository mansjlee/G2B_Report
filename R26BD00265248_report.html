사업 개요 및 목적
  • 혈액관리법에 따라 의료기관이 혈액 사용 정보(사용량·재고량·폐기량 등)를 보건복지부에 의무 제출해야 하는 제도를 수기 방식에서 API 자동 연계 방식으로 전환·확대하는 사업
  • 혈액수급관리시스템(BMS)에 연계되지 않은 281개소 의료기관의 데이터 연계를 추진하고, 의료기관의 연계 개발 부담 최소화를 위한 연계 지원 프로그램 4종을 개발·배포함

  • 과년도 2단계 사업(104개소 연계)에 이어 3단계로 추진되는 연계 확대 사업임

불가능 요소
  • 통합발주 SW 없음: 붙임7 직접구매 대상 상용소프트웨어 목록에 DB 암호화 솔루션(2식) 1개 품목만 존재하며, Red Hat 상용 제품은 전혀 명시되지 않음
  • OS/플랫폼 제공주체 별도: 운영체제(OS), WEB, WAS, DBMS 등 시스템 SW는 국가정보자원관리원이 제공·관리하므로 Red Hat이 RHEL 등을 별도 제안할 여지가 없음 (ECR-001, ECR-002)
  • 공개 SW 중심 구성 원칙: ECR-003에 "공개 SW 중심의 소프트웨어로 구성하며, 보안·운영·관리에 필요한 최소한의 SW 도입"을 명시하여 상용 Red Hat 제품 도입 환경이 제한적임
  • Red Hat 상용 제품명 전무: RFP 전문에 RHEL, OpenShift, Ansible, JBoss EAP, Satellite 등 Red Hat 상용 제품명이 단 한 건도 언급되지 않음
  • 순수 SI·용역 중심 사업: 사업의 핵심은 소프트웨어 개발·연계 용역이며, 상용 SW 납품 규모가 DB 암호화 솔루션에 한정됨
  • 경쟁/대체 제품 명시: 없음 (경쟁 OS나 플랫폼이 명시된 것은 아니나, Red Hat 도입 근거 자체가 없음)
Red Hat 제안
가능 요소
  • Java 기반 개발 환경: 전자정부 표준프레임워크(Java 기반) 적용 및 Java 언어 개발이 중심이나, WAS는 국가정보자원관리원 제공 환경을 준용해야 하므로 JBoss EAP 별도 제안이 현실적으로 어려움
  • Linux 플랫폼 활용: 기술적용계획표에 Linux 서버 OS 적용이 명시되어 있으나, 해당 OS는 국가정보자원관리원이 제공·운영하는 범정부 자원 통합 환경에 해당하여 Red Hat이 직접 제안하기 어려운 구조임
  • RESTful API·컨테이너 인프라 잠재성: API 게이트웨이, 연계 지원 프로그램 배포 등 구조상 컨테이너(OpenShift) 기술 활용 여지가 있으나, RFP에 컨테이너·Kubernetes 관련 요건이 전혀 명시되지 않음
  • RFP 내 Red Hat(동의어 포함) 제품명 및 수량: 해당 없음 — RFP 전문에 Red Hat 또는 동의어에 해당하는 제품명이 명시된 바 없음
  • 종합 평가: 제안 가능 요소가 매우 미약하며, 실질적인 영업 기회로 연결되기 어려운 구조의 사업임
