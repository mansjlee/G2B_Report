불가능 요소
  • Red Hat 제품 직접 S/W 공급 사업이 아님: 소프트웨어 직접구매 제외 및 통합발주 원칙으로 수행사(SI)가 H/W·S/W 일괄 납품·탑재 구조
  • RHEL·OpenShift·Ansible·JBoss 등 Red Hat 제품명이 RFP 필수 규격에 명시되지 않음
  • SSL VPN Client는 「센터와 호환되는 제품」으로 규정되어 기존 김포시 CCTV통합관리시스템·VPN 체계 종속 가능성 높음
  • 영상분석·객체검출·이벤트검출 S/W는 딥러닝 기반 전용 솔루션으로 규격화되어 Red Hat 대체 불가 영역
  • 현장 장비는 ARM Cortex 임베디드·LTE 라우터·LED 전광판 등 특수 HW/SW 중심으로 서버 OS 라이선스 수요가 제한적
  • 기술적용계획표상 서버 OS는 Linux·Windows Server·UNIX 등 다중 선택지이며 RHEL 지정 없음
  • 입찰참가자격에 정보통신공사업·소프트웨어사업·중소기업 직접생산확인(안내전광판·금속기둥·정보시스템개발) 등 SI·시공 역량 요건이 핵심
Red Hat 제안
가능 요소
  • 스마트 통합관리 플랫폼 서버(수집·이벤트·API·DB·스토리지)에 RHEL을 플랫폼 OS로 제안 가능(기술적용계획 Linux/POSIX 호환 서버 환경)
  • CUR-002 MSA 적용·RESTful API 연계 설계 요구에 OpenShift Container Platform 기반 마이크로서비스·API Gateway 아키텍처 제안 가능
  • 다수 현장 서비스·장비 통합 운영·배포 자동화에 Ansible Automation Platform 적용(설정·패치·장애대응) 제안 가능
  • 통합관제·KPI·통계·365일 무중단 운영 요구에 RHEL 고가용성(RHEL HA)·모니터링 연계 솔루션 제안 가능
  • 향후 김포시 스마트도시 통합플랫폼·공공데이터 API 확장 시 컨테이너 기반 표준 연계(OpenShift+API)로 차별화 제안 가능
  • Red Hat은 SI·통신사·스마트시티 구축사 파트너 채널을 통해 하도급·공동수급 형태로 플랫폼·OS·자동화 라이선스 공급 및 기술지원 제안 가능
