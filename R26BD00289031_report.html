불가능 요소
  • [경쟁 제품 명시] 유지관리 대상 상용 SW 12종이 모두 TmaxSoft(WebtoB, JEUS), 이니텍, 솔트룩스 등 비(非) Red Hat 제품으로 구성되어 있으며, RFP 및 요구사항 전체에 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 단 한 건도 언급되지 않음
  • [기존 WAS 스택 고정] 현행 WEB/WAS 서버는 WebtoB·JEUS(TmaxSoft)로 운영 중이며, 개발자 요구 스펙에 "Java, Javascript, Oracle, JSP, WebtoB, JEUS" 명시 → JBoss EAP 전환 여지 극히 낮음
  • [S/W 직접 납품 구조 없음] 상용 SW 유지관리 비용은 사업자(수행사)가 직접 부담하는 구조로, Red Hat이 별도 SW 공급자로 참여하기 어려운 계약 형태
  • [대기업 참여 제한] 총예산 20억 미만으로 중소기업만 입찰 가능, Red Hat Korea가 직접 입찰 참여 불가 (하도급 또는 제조사 기술지원 형태로만 간접 참여 가능)
  • [서울시 데이터센터 통합인프라 운영] WAS·WEB·DB 서버 및 형상·배포·모니터링 서버 모두 서울시 데이터센터(통합인프라)에서 운영 중으로, 인프라 OS 교체 기회 없음
Red Hat 제안
가능 요소
  • [신규 민간 클라우드 환경 - 제한적 기회] 서울형 낀세대 연금 시스템은 발주사가 신규 도입 예정인 민간 클라우드에 구축하며, WEB/WAS 소프트웨어를 제안사(계약상대자)가 직접 설치·운영 → 클라우드 VM의 OS 선택에 RHEL 제안 여지 존재. 단, 기존 패턴상 TmaxSoft 계속 사용 가능성 높음
  • [기술 적용 계획표 Linux 명시] 기술적용계획표에 "Linux"가 서버용 운영체제로 적용 대상에 포함되어 있어, RHEL 제안을 위한 최소한의 기술적 근거 존재 (OS 브랜드 미지정 상태)
  • [클라우드 컴퓨팅(IaaS/PaaS) 적용 계획] 기술 표준에 IaaS/PaaS 적용이 명시되어 있어 클라우드 네이티브 환경 구성 시 RHEL, OpenShift 제안을 위한 기회 요소로 활용 가능
  • [Java 기반 개발 환경] Java·JSP 기반 전자정부 표준프레임워크 사용으로, 이론적으로는 JEUS를 JBoss EAP로 대체 제안 가능하나, 기존 TmaxSoft 유지관리 계약 구조상 현실적 전환 가능성 낮음
  • [RFP 내 Red Hat(또는 동의어) 제품명·수량] 해당 사항 없음 — RFP 전체에 Red Hat 상용 제품명 또는 동의어가 전혀 명시되지 않음
