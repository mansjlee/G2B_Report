해양환경공단 - 해양환경공단 KOEM AI 구축 - 분석 리포트

레드햇 제안 가능성 중간
OS 미지정 GPU 서버, RHEL·OpenShift AI 제안 여지
사업 개요 및 목적
  • 해양환경공단(KOEM)의 자체 AI 플랫폼이 부재하고 데이터 완결성이 부족한 현황을 극복하기 위해 온프레미스 기반 생성형 AI 플랫폼(LLMOps)을 신규 구축하는 사업
  • GPU 인프라 확보, LLM/VLM 기반 Agentic AI 구현, RAG 시스템 구축을 통해 전사 AI 활용 표준화 및 실질적 업무 혁신 추진
  • 5대 AI 서비스(문서 초안 작성, 주요 규정 질의응답, 외부 인터넷 연계 질의, 위험성 평가 지원, 해양방사능 분석데이터 검증) 구현
  • 전자결재·인사·감사 등 기존 정보시스템과 AI 플랫폼 연계(MCP, API 등)를 통한 Agentic AI 기반 업무 자동화 실현
주요 정보
  • 사업 예산: 1,387,567,000원 (VAT 포함)
  • 사업 기간: 착수일로부터 8개월 (추진일정상 2026년 10월 착수 ~ 2027년 5월 완료 예정)
  • 사업 범위:
    • ① AI 플랫폼(LLMOps) 도입 및 5대 AI 서비스 구축
    • ② GPU 서버(H200급 SXM, 4GPU 이상) 1대, UPS 2대, 표준랙·PDU, L3 스위치 2대 등 신규 인프라 구축
    • ③ 기존 VMware(ESXi) 서버 3식 RAM 증설(256GB→512GB 이상)
    • ④ 오픈소스 기반 LLM(VLM), RAG(Advanced RAG), Vector DB, AI 서비스 빌더, 가드레일, SSO·DRM 연계
  • 주요 일정:
    • 2026년 10~11월: GPU 등 인프라 설치, LLM·RAG 구축 착수
    • 2026년 12월 ~ 2027년 2월: AI플랫폼 I/F 구축(MCP, API 등), AI 응용 서비스 개발
    • 2027년 3~4월: 테스트 및 가동·안정화
    • 2027년 5월: 시범 오픈
    • 계약방법: 제한경쟁입찰, 협상에 의한 계약, 나라장터 공고

핵심 요구사항
  • [핵심 기술 요구사항]
    • 온프레미스 LLMOps 플랫폼: 검색DB·임베딩모델·서비스관리·운영관리 기능 포함, no-code 서비스 빌더, 가드레일 관리, Vector DB 관리, MLOps 추가제안 가능
    • LLM/VLM 모델: 오픈소스(오픈웨이트) 기반, 멀티모달(VLM) 지원, 입력 30K tokens·출력 8K tokens 조건에서 정상 응답, 한국어 정확도 85% 이상, 동시 접속 100명(동시 질의 25명) 이상 처리
    • Advanced RAG: Self-Reflective RAG, Query Rewrite, Hybrid Search, Re-ranking, 외부 검색 API(Search Engine) 연동, 하이브리드 RAG 구조
    • 인터페이스 연계: 반디SSO(SSO 연계), 파수 DRM(자동 복호화 연계), 전자결재·인사·선박관리·감사·예산 등 기존 정보시스템 연계
    • 보안: AI 입출력 가드레일, 에이전틱 AI 화이트리스트 도구 제어, 감사로그, 국정원 생성형 AI 보안 가이드라인 준수
  • [통합발주 S/W 구매 목록]
    • RFP 내 통합발주용 명시 상용 S/W 품목 및 수량이 구체적으로 지정되어 있지 않음. 제안사가 자율적으로 솔루션 선택·제안하도록 설계됨
    • 단, 다음 SW 라이선스는 사업 내 반드시 포함 필요 (SFR-003): "LLMOps, RAG, 프롬프트 서비스, 타 시스템 연계 API 등 AI 서비스를 위한 모든 소프트웨어 라이선스 포함"
    • AI 모델(LLM/VLM): 오픈소스 기반 권장, 상용 모델 제안 시 TCO 제시 요건 (수량: 전직원 무제한 사용 라이선스)
    • GPU 서버 OS: 명시 없음. ECR-006에 "보안패치 기술지원 가능 OS" 요구 (수량: 1식)
    • L3 스위치 소프트웨어(보안기능확인서 발급 제품): 2대
    • VMware 서버 RAM(메모리 모듈): 서버 3식 × (512GB 이상 구성용 증설분)
Red Hat 제안
불가능 요소
  • [경쟁 제품 명시]: ECR-005에서 기존 운영 중인 VMware(ESXi) 서버 3식의 RAM 증설이 과업으로 포함되어 있어, 해당 서버의 가상화 플랫폼은 VMware로 확정된 기존 환경임. 단, 이는 신규 AI 인프라가 아닌 기존 자원 증설임
  • [Red Hat 상용 제품 미명시]: RFP 전체에 RHEL, OpenShift, Ansible, JBoss/EAP, Satellite 등 Red Hat 상용 제품명이 구매·납품 품목으로 명시되어 있지 않아 "높음" 판정 불가
  • [오픈소스 AI 플랫폼 선호]: LLM/VLM 모델은 "오픈소스(오픈웨이트) 기반"을 원칙으로 명시하고 있어, Red Hat OpenShift AI나 RHEL AI 등 상용 AI 제품의 직접 납품 기회는 제한적
  • [OS 지정 없음 = 경쟁 환경]: GPU 서버 OS가 지정되지 않아 Ubuntu, Rocky Linux 등 경쟁 배포판 제안도 가능한 상황
Red Hat 제안
가능 요소
  • [GPU 서버 OS → RHEL 제안 기회]: ECR-001(GPU/HGX 서버 1대), ECR-006에서 "설치되는 모든 서버의 OS는 보안패치 기술지원이 가능해야 함"으로 명시. 특정 OS 미지정으로 RHEL(Red Hat Enterprise Linux) 제안 가능. NVIDIA DGX/HGX 서버의 RHEL 공식 지원(NVIDIA-Certified System) 강점 활용 가능
  • [AI 플랫폼 인프라 → OpenShift AI / RHEL AI 제안 기회]: 온프레미스 LLMOps 플랫폼, 컨테이너 기반 AI 서비스 운영 환경에 Red Hat OpenShift AI(구 RHODS) 또는 OpenShift Container Platform(OCP) 제안 여지. RAG 파이프라인, 모델 서빙, MLOps 등 요구사항이 OpenShift AI의 핵심 기능과 부합
  • [Ansible 자동화 제안 기회]: GPU 서버·네트워크·UPS 등 인프라 구성 자동화 및 AI 플랫폼 운영 자동화에 Ansible Automation Platform(AAP) 제안 가능
  • [공공 보안 요건 부합]: SER 보안 요구사항(접근통제, 감사로그, 취약점 점검, SBOM 제출 등) 다수 포함. RHEL의 공공기관 보안인증(CC인증, FIPS 등) 및 서브스크립션 기반 보안패치 지원이 경쟁 우위
  • [RFP 내 Red Hat 제품명 직접 명시]: 없음 (상용 RH 제품 품목 미기재)
