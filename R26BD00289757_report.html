국립농업과학원_2027년 농업과학기반기술 정보서비스 통합 운영 - 분석 리포트

레드햇 제안 가능성 중간
Linux 미지정·WildFly→EAP 제안여지
사업 개요 및 목적
  • 국립농업과학원이 운영하는 5개 농업 정보시스템(흙토람·농업날씨365·씨앗은행·농업인안전365·대표홈페이지)의 2027년 통합 운영, 유지보수 및 기능 개선 사업
  • 토양환경·농업기상·유전자원·건강안전·기관홍보 서비스의 지속적 안정 운영과 대국민 서비스 품질 고도화가 핵심 목표
  • G-클라우드(국가정보자원관리원 대구센터) 기반 클라우드 자원 최적화 및 정보보안 강화 포함
  • 농업 관련 공공데이터 개방·확산, 웹 접근성 인증 유지, 시스템 간 데이터 연계 등 공공 정보 인프라 현행화
주요 정보

  • 사업 기간: 2027. 1. 1. ~ 2027. 12. 31. (1년)

  • 주요 일정: 착수(M) → 분석(M~M+2) → 설계(M+2~M+5) → DB구축·구현(M+2~M+11) → 운영지원(M~M+11, 상시). 입찰방식: 조달청을 통한 중소기업자간 제한경쟁입찰(협상에 의한 계약)

    • 씨앗은행(GMS): 식물유용미생물 통합서비스 관리자 페이지 GMS 구축, 그린마이크로바이옴뱅크 웹서비스 이관, 바이오뱅크 시료 DB 관리자 페이지 구축, GMS 자원정보 기능개선, 온라인 분양·기탁 서비스 개선, 식물바이러스 분양승인서 출력 기능 추가, 빅데이터(이미지·유전체) 자료관리 연계, 허바리움 기능개선
    • 농업인안전365: VR 안전교육 자료관 대민서비스 신설, 농작업 사고사례 현행화(약 50건), 통계DB 3종 현행화(업무상 질병·사망재해·유관기관)
    • 대표홈페이지: 게시판 첨부파일 바로보기 기능 추가, 현장기술수요·신기술보급사업 유지관리, 모바일공무원증 로그인 구현
    • 공통: 5개 시스템 정책변경 긴급지원, 웹접근성 인증 갱신(대표홈페이지·농업인안전365 2개소), 데이터품질관리, 정보보안·개인정보보호 조치, 클라우드 운영 지원
  • [구매 명시 S/W]: 본 RFP는 시스템 운영·유지보수·기능개선 용역 사업으로, 별도 통합발주 상용 S/W 품목은 명시되지 않음. 단, 제약사항(COR-003)에 "시스템 구축에 필요한 SW를 도입할 경우 개발비에 포함하여 제안하고, 제품가격과 라이선스를 제출"하도록 규정되어 있어 제안사 재량에 따른 소규모 SW 도입이 포함될 수 있음. 현 시스템에 사용 중인 주요 SW: Hyperframe(WAS 프레임워크), WildFly(WAS), JDK, EDB(PostgreSQL 계열 DBMS), Tibero(DB), Konan Search(검색), Crownix Report(리포팅), Synap Document Viewer(문서뷰어), GeoServer/MapServer(GIS)
Red Hat 제안
불가능 요소
  • Red Hat 상용 제품 명시 없음: RFP 전문 및 과업지시서, 전산자원 현황 어디에도 RHEL, OpenShift, JBoss EAP, Ansible, Satellite 등 Red Hat 상용 제품이 구매·납품 품목으로 명시되지 않음
  • WildFly(커뮤니티 제품) 사용 중: 현재 WAS로 WildFly(Red Hat의 업스트림 커뮤니티 제품)가 사용 중이나, 이는 JBoss EAP 상용 제품과 동일하지 않으므로 높음 판정 근거 불가. WildFly 기반 현행 운영 환경에서 EAP 전환 제안은 가능하나 저항이 있을 수 있음
  • 주요 경쟁·비 RH DB 사용 중: EDB(EnterpriseDB, PostgreSQL 계열)와 Tibero가 DBMS로 사용 중. Red Hat 자체 DBMS 라인업과 직접 경쟁하지는 않으나 플랫폼 교체 여지 제한
  • Hyperframe WAS 프레임워크 종속: 행정공공기관 표준 WAS 프레임워크인 Hyperframe(전자정부 표준프레임워크 기반)이 적용되어 있어 미들웨어 교체 난이도 높음
  • 용역 중심 사업 구조: 사업의 핵심이 SW 납품이 아닌 운영·유지보수·기능개선 용역으로, Red Hat 구독 라이선스 직접 발주 구조가 아님. SI·통합사업자가 납품 결정권을 가짐
  • 중소기업 제한경쟁입찰: 대기업(Red Hat Korea) 직접 참여 불가. 파트너사를 통한 간접 제안 구조
Red Hat 제안
가능 요소
  • OS 미지정 → RHEL 제안 여지: 전산자원 현황표에 운영체제가 "Linux"로만 표기되어 있고 특정 배포판이 명시되지 않음. Ubuntu, Rocky Linux, CentOS 등 경쟁 OS도 명시되지 않아 RHEL 제안 및 포지셔닝 가능
  • WildFly → JBoss EAP 전환 제안 여지: 현재 전체 WAS(외부·내부·연계서버 포함 다수 노드)에 WildFly가 사용 중. WildFly의 상용 지원 버전인 JBoss EAP로의 전환 또는 신규 도입을 제안하여 엔터프라이즈 지원·보안패치·SLA를 강점으로 어필 가능
  • 클라우드 자동화 → Ansible Automation Platform 제안 여지: G-클라우드(대구센터) 기반으로 5개 시스템이 운영 중이며, 클라우드 자원 최적화·성능관리·장애대응 등 운영 자동화 요구사항이 명확함. Ansible Automation Platform을 통한 클라우드 운영 자동화 제안 가능
  • 컨테이너/PaaS 플랫폼 검토 여지: 기술적용계획표에 IaaS·PaaS·SaaS 모두 적용 대상으로 분류되어 있으며, 향후 시스템 고도화 과정에서 OpenShift Container Platform 제안 가능성 존재
  • 강화된 보안 요구 → RH 보안 솔루션 연계: 시큐어코딩, 웹 취약점 점검, 접근통제, 개인정보 안전성 확보 등 13개 보안 요구사항이 명시되어 있어 Red Hat 기반 보안 아키텍처(ACS, Ansible 보안 자동화 등) 제안 가능
  • RFP에 명시된 Red Hat(또는 동의어) 제품명·수량: 해당 없음 (RFP 내 Red Hat 상용 제품명 명시 전무)
