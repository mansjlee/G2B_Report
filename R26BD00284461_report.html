Red Hat 제안
불가능 요소
  • Red Hat 상용 제품 미명시: RFP 전문 및 별첨·별지 전체에 걸쳐 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 구매 품목으로 명시되어 있지 않음
  • SW 세부 내역 비공개: 유지관리 대상 상용SW 108본의 구체적인 제품명·수량은 보안 사유로 비공개 처리되어 있어 Red Hat 제품 포함 여부를 RFP 문서상에서 확인 불가 → 영업 활동을 통한 사전 파악 필요
  • 신규 SW 납품 가능성 낮음: 본 사업은 기존 구축된 시스템의 유지관리(운영·패치·장애대응)가 주목적으로, 신규 상용SW 도입 예산이 별도 책정되어 있지 않음 (예산 구조: HW/SW 유지관리 + 인력 상주용역)
  • 특정 경쟁 제품 명시: 클라우드 보안관제 솔루션으로 E-ADS-C(넷코아테크, 케리스)가 명시되어 있으며, 본 사업 기간 동안 라이선스 유지 보장 의무 부과
  • 중소기업 한정 입찰: 사업금액 20억 미만 제한으로 대기업·중견기업 참여 불가 → Red Hat Korea가 직접 수주 불가, 파트너 영업 전략 필수
Red Hat 제안
가능 요소
  • Linux 기반 OS 운영 환경 확인: MHR-002(통합지원센터 인력 요건)에서 "O/S(Linux/Unix/Windows), WEB/WAS, DBMS 운영 지원" 능력을 명시적으로 요구 → 현 시스템이 Linux 계열 OS를 사용 중임을 시사, RHEL 제안 여지 존재
  • 컨테이너·K8s 환경 운영 중: 별첨6(클라우드 보안관리) 내 "독립된 K8s 구성으로 안전 분리 준수", "Network Policy를 통한 논리 방화벽 구성" 등 컨테이너 플랫폼 보안 지침 명시 → OpenShift 제안 여지
  • AI·LLM 서비스 인프라 운영: GPU 서버(Dell PowerEdge R770, H200·L40S GPU) 기반 LLM 파인튜닝·RAG 파이프라인·Hugging Face 모델 운용 환경 → RHEL AI / OpenShift AI 제안 가능성
  • 상용SW 108본 세부 내역 불명: 비공개 처리된 상용SW 108본 목록에 RHEL 등 Red Hat 제품이 포함되어 있을 가능성을 배제할 수 없음 → 발주처 방문 열람 또는 수행 파트너를 통한 사전 확인 필요
  • OS 패치·업그레이드 지원 의무: MAR-013에서 OS Patch Release, Hot Fix 수준의 Upgrade 지원을 명시 → 기존 RHEL 구독이 존재할 경우 구독 갱신 또는 확장 영업 기회
  • RFP에 명시된 Red Hat(또는 동의어) 제품명·수량: 해당 사항 없음 (RFP 문서상 Red Hat 상용 제품명 미확인)
  • 영업 접근 전략 제언: ① 발주처 방문 열람(보안서약서 제출)을 통해 SW 108본 목록 확인 → RHEL 포함 여부 파악, ② 입찰 참여 중소기업 파트너(SI)를 통한 사전 협력 구도 구성, ③ GPU 서버 기반 AI 인프라에 RHEL AI / OpenShift AI 차기 사업 연계 제안
