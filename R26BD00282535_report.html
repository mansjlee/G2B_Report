Red Hat 제안
불가능 요소
  • [S/W 품목 비공개] SW 현황이 "방문 보안 서약 후 열람 가능"으로 처리되어, 통합발주 상용 S/W 목록에 Red Hat 제품 포함 여부를 현 단계에서 확인 불가
  • [Red Hat 상용 제품 미명시] RFP 전체에 RHEL, OpenShift, Ansible AAP, JBoss EAP 등 Red Hat 상용 제품명이 품목으로 명시되지 않음 → 높음 판정 근거 없음
  • [경쟁 제품 미명시 — 긍정적] Ubuntu, Rocky Linux, VMware, Oracle Linux 등 경쟁 제품도 명시되지 않아 Red Hat 진입 장벽은 없음
  • [순수 SI 성격] 주 사업 내용이 소프트웨어 개발·재구축 용역이며, 시스템 인프라(H/W·S/W)는 기존 현황 비공개로 도입 확정 여부 불명확
  • [중소기업 전용 사업] 20억 미만으로 대기업·중견기업 참여 불가 → Red Hat 직접 참여 불가, 파트너사를 통한 간접 제안 필요
  • [오픈소스 활용 허용] "오픈소스인 경우 불법소프트웨어 등 하자가 없어야 함"으로 명시 → 커뮤니티/오픈소스 대체 가능성 존재
Red Hat 제안
가능 요소
  • [RHEL 제안 가능] 기술적용계획표에 서버용 운영체제로 "Linux ○" 명시 — 특정 배포판 미지정으로 RHEL 제안 가능. 상시 보안패치·클라우드 네이티브 환경 요구와 RHEL의 Enterprise 지원 강점 일치
  • [OpenShift 제안 가능] MSA 지향 구조 + 컨테이너(도커) + 쿠버네티스 보안설정(RBAC, mTLS, CVE 취약점 점검, CI/CD 보안스캐너) 명시 → OpenShift의 엔터프라이즈 K8s 플랫폼 및 내장 보안 기능(ACS, Quay 등)으로 차별화 제안 가능
  • [Ansible AAP 제안 가능] CI/CD 자동화 파이프라인, 58개 공동활용기관 대상 단계적 배포·전환 계획, 컨테이너 배포 절차 자동화 요구 → Ansible Automation Platform 제안여지
  • [민간 클라우드 IaaS 환경] CSAP 인증 민간 클라우드 서비스 요구 — RHEL 기반 IaaS 인프라로 구성 제안 가능
  • [보안 강화 요구사항과 RH 강점 일치] 컨테이너 취약점 점검(CVE), 서명·무결성 검증, 롤백·배포 절차, 감사 로그 수집 등 → OpenShift + ACS(Advanced Cluster Security) + Quay(컨테이너 레지스트리) 통합 제안
  • [RFP 내 Red Hat 제품명 명시 여부] 문서 전체에 Red Hat 상용 제품명(RHEL, OCP, Ansible 등) 직접 명시 없음. 단, SW 현황 비공개로 실제 도입 목록 추가 확인 필요 (현장 방문 후 파악 권장)
  • [영업 접근 전략] 파트너(중소 SI) 지원 방식으로 접근 필요. 기술적용계획표의 Linux·DBMS·IaaS 항목을 근거로 선제 제안 가능. 58개 공동활용기관 확산 시 RHEL/OpenShift 구독 확대 기회 존재
