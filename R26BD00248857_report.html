  • 사업 기간: 계약체결일로부터 360일 이내
  • 사업 범위: 연탄전환·등유/LPG 지원 시스템 개발, 카드사(현대카드) 추가·정산방식 변경, 자동전환·예외지급·통계·챗봇·보안 기능 개발, 시스템 운영지원 및 교육(연 1회 이상)

  • 평가: 기술능력 90% + 입찰가격 10%(기술 85% 미만 협상 제외), 하도급 불허, 중소 SW사업자만 참가 가능(20억 미만)

Red Hat 제안
불가능 요소
  • S/W 공급 미포함: 본 사업은 정보시스템 기능개발·고도화·운영지원 용역이며, Red Hat 제품(RHEL·OpenShift·Ansible 등)의 조달·도입·라이선스 공급 범위가 명시되지 않음
  • 경쟁·기존 스택 고정: 현행 시스템에 JEUS8(WAS), WebToB5(웹서버), ORACLE 19c(DBMS)가 명시되어 있어 Tmax·Oracle 기반 유지가 전제됨
  • 개발 제약: COR-004에 웹은 JSP, 연계는 JAVA(HTML5), COR-002에 전자정부 표준프레임워크 적용 원칙 → 기존 공공 SI 아키텍처 변경 여지 없음
  • 기존 호환 의무: PER-001·COR-006에 기존 시스템 구조·호환성·운영 영향 최소화 요구 → 미들웨어·DB·OS 전환 제안 곤란
  • 하도급 불허·중소 SW사업자 제한: Red Hat이 직접 SI 수행 주체가 될 수 없고, 대형 통합 SI가 아닌 중소 SW업체 대상 사업
  • 인프라 변경 없음: HW는 웹/WAS/DB 가상서버 및 L4(RADWARE ALTEON)로 기재되어 있으나 본 과업은 애플리케이션 기능개발에 한정
Red Hat 제안
가능 요소
  • 간접·제한적: 기술적용계획표에 Linux·클라우드(IaaS/PaaS/SaaS) 항목이 '적용'으로 표기되어 있으나, 현행 JEUS·Oracle·WebToB 구성과 충돌하며 본 RFP 과업범위에 OS·컨테이너·클라우드 전환 요구는 없음
  • Ansible: 자동전환·배치·운영 자동화 등 운영 효율화를 제안서 부가 기술로 언급 가능하나, RFP 필수 요구사항·평가항목에 포함되지 않아 실질 채택 가능성 낮음
  • RHEL/OpenShift: 가상화 서버 OS·컨테이너 플랫폼 전환 시 Red Hat 스택 적용 여지는 이론상 존재하나, 기존 JEUS·Oracle 호환·무중단 운영 제약으로 본 사업 범위 내 직접 제안은 부적합
  • JBoss: COR-004의 JAVA/JSP 개발 환경과 WAS 교체 시 대안 가능성은 있으나, JEUS8 현행 운영 및 기존시스템 호환 요구로 교체 제안은 현실성 낮음
  • 결론: Red Hat 제품 직접 판매·라이선스 제안 기회는 거의 없으며, 협력사(SI) 경유 간접 기술 자문·아키텍처 제안 수준만 검토 가능
