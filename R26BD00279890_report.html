사업 개요 및 목적
  • 한국기술교육대학교 온라인평생교육원이 운영하는 스마트 직업훈련 플랫폼(STEP)의 SDDC 가상화 서버 성능 업그레이드 및 노후 DB서버 교체 사업
  • AI·다국어 직업훈련 확대, LMS 분양기관 증가에 따른 클라우드 인프라 확장 및 안정적 운영 기반 확보
  • 노후 DB 하드웨어(2019년 도입)·DBMS(Oracle 12c) 버전 경과에 따른 최신 안정화 버전(Oracle 26ai) 전환 및 재해복구(DR) 체계 신규 구축
  • 현재 48대 물리 서버에서 1,627대 가상서버를 운영 중이며, 신규 LMS 분양·AI 콘텐츠 확대로 가상서버 및 관리 자원 지속 증가 예상

    • ③ STEP DB시스템 H/W 재구축 (고성능 DB Appliance, 1식)

Red Hat 제안
불가능 요소
  • Oracle DBMS 제품 특정 명시: ECR-04에서 Oracle Database Enterprise Edition 26ai를 동일 제조사 제품으로 명시 특정. "타 제조사 DBMS로 대체할 경우 기존 응용프로그램 SQL·프로시저 전면 재개발, Advanced Security 적용 데이터 변환, 데이터 이관 정합성 검증 등으로 현저한 비용 상승과 사업 지연이 초래"라고 적시하여 대체 불가 선언 → Red Hat JBoss/Quay 등 제안 완전 불가
  • Oracle Active Data Guard 제품 특정 명시: ECR-05에서 "운영 DBMS와 동일 제조사의 재해복구 솔루션(Oracle Active Data Guard)으로만 요구 기능의 완전한 충족이 가능"하다고 명시하여 제품 특정 → Red Hat DR 관련 솔루션 제안 불가
  • DB 어플라이언스 OS는 Oracle Linux 추정: ECR-03에서 "DB 제조사의 정품 제공", "펌웨어·운영체제·이중화 솔루션·DB가 통합 패치 번들 형태로 설치"를 요구 → Oracle ODA(Oracle Database Appliance) 구성으로 Oracle Linux 환경이 확실시되어 RHEL 제안 불가
  • 기존 SDDC 환경 호환성 종속: ECR-01에서 "기존 STEP SDDC 관리 클러스터와 동일 운영환경으로 통합 구성 가능해야 하며 기존 가상화 플랫폼·네트워크·스토리지와 호환성"을 요구 → 기존 가상화 플랫폼(보안상 비공개) 종속으로 Red Hat 가상화(RHEV) 신규 제안 사실상 불가
  • Red Hat 상용 제품명 전혀 미명시: RFP 전체 문서에서 RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 단 한 건도 언급되지 않음
Red Hat 제안
가능 요소
  • RFP 내 Red Hat 상용 제품명 명시: 없음
  • Linux 기반 운영환경 언급: ECR-04에서 "Linux 기반 운영환경을 지원해야 함"이라는 조건이 있으나, DB 어플라이언스 특성상 Oracle Linux 환경으로 귀결될 가능성이 높아 RHEL 제안 실질적 여지 없음
  • IaaS/클라우드 컴퓨팅 기술 적용: 기술적용계획표에 IaaS/PaaS/SaaS 항목이 기재되어 있으나, 기존 SDDC 환경 확장 사업 특성상 신규 플랫폼 도입 여지 없음
  • 종합 평가: 본 사업은 Oracle DBMS·DR 솔루션이 제품 특정으로 고정되어 있고, SDDC 증설은 기존 환경 호환성에 종속되어 Red Hat 상용 제품이 진입할 실질적 기회가 없는 사업임. 향후 Oracle DB 환경 위에 운영되는 미들웨어·자동화 영역(JBoss EAP, Ansible 등)에 대한 별도 사업 발굴 관점으로 접근 권장
