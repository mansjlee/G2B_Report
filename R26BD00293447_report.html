불가능 요소
  • S/W 공급 미포함: 본 사업은 정보시스템 유지관리 용역으로, 신규 S/W 구매·구독 납품 품목이 명시되어 있지 않음
  • JBoss가 '공개SW'로 분류: JBOSS 7.4가 상용SW가 아닌 공개SW로 관리되고 있어, 현재 Red Hat 구독(서브스크립션) 없이 운영 중일 가능성이 높으며 RFP상 구독 갱신·도입 예산 미반영
  • 경쟁 제품 명시 여부: VMware, Ubuntu, Rocky/Oracle Linux 등 경쟁 OS·가상화 제품 명시 없음. 다만 서버 OS·DBMS 정보도 미공개(누출금지 대상정보로 분류)
  • 입찰 구조 제약: 20억 미만 중소SW사업자 전용 사업으로 대기업 참여 제한, 낙찰 SI사의 재량에 의존해야 하며 예산 768백만원 내 인건비 비중이 높아 구독비 반영 여력 제한
  • 선발주 리스크: 2027년 예산 확정 전 선발주로 예산 삭감 시 과업범위 축소 가능
Red Hat 제안
가능 요소
  • RFP 명시 Red Hat(동의어) 제품: JBOSS 7.4 (WAS서버, 공개SW 항목) - 수량 미기재 / 그 외 RHEL, OpenShift, Ansible 등 명시 없음
  • JBoss EAP 구독 전환: JBoss 7.4는 JBoss EAP 7.4 계열로 판단되며, 공개SW로 무지원 운영 중이라면 보안 패치·기술지원 확보를 위한 EAP 정식 구독 전환 제안 가능 (SER-011 취약점 조치, SLA 가용률 요구와 연계)
  • EAP 8 업그레이드: COR-001 전자정부 표준프레임워크 최신 버전 업그레이드 요구 시 Jakarta EE 기반 WAS 필요 → JBoss EAP 8 업그레이드 및 라이프사이클 대응 제안
  • OS·인프라 전환 기회: MAR-001에 "시스템(HW, OS, NW, DBMS) 신규도입·업그레이드", "클라우드 이전 및 OS 변경" 지원이 명시되어 있고 OS 미지정 → RHEL 제안 여지
  • 운영 자동화: 매월 예방점검, 자원(CPU·메모리·DB) 모니터링, WEB/WAS/DBMS 점검보고 → Ansible Automation Platform 기반 점검·패치 자동화로 SLA(예방점검 준수율) 대응 강점
  • 연계·API 현대화: OPEN API 연계 에이전트 개발 및 실시간 상태 모니터링 → Red Hat build of Apache Camel/AMQ, 3scale 등 통합 솔루션 또는 향후 OpenShift 기반 컨테이너화 제안 여지
  • 영업 전략: 발주기관(연구협력과)에 JBoss 무지원 운영 리스크를 사전 인지시켜 차년도 별도 구독 예산 편성 유도, 낙찰 중소 SI사와 협력하여 유지관리 범위 내 EAP 구독 반영 제안
