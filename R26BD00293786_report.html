불가능 요소
  • S/W 신규 공급 미포함: 신규 S/W 구매·통합발주 품목은 없으며, 기존 장비·S/W의 통합유지관리 용역(인력 상주 중심) 사업임
  • 경쟁 제품 명시: OS에 Microsoft(Windows), IBM(AIX), Rocky, Ubuntu, CentOS / 가상화에 VMware / WAS에 JEUS·WebtoB·Tomcat·WildFly / DBMS에 Oracle·Tibero·MSSQL / 빅데이터에 Oracle Cloudera 등 다수 경쟁·대체 제품이 운영 중
  • 공개SW 자체 지원 위험: Redhat Ent, Jboss EAP가 '공개SW'로 분류되어 있어, 사업자가 서브스크립션 갱신 없이 자체 인력 기술지원으로 대응할 가능성 존재
  • 수량 비공개: OS 56식·공개SW 503식 중 Red Hat 제품의 정확한 수량·버전은 보안상 미공개로 사전 규모 산정 곤란
  • 참여 제약: 대기업·상호출자제한기업 참여 불가(중소·중견 SI만 입찰), 국제입찰 제외, 하도급 50% 제한·재하도급 금지로 Red Hat 직접 참여 불가 → 파트너 경유 공급 구조
  • 예산 구조: 인력 9명 상주 비용 비중이 커서 서브스크립션 비용 반영 여력이 제한될 수 있음
Red Hat 제안
가능 요소
  • RFP 내 Red Hat(동의어) 제품명·수량
    • RedHat (OS) — 상용 OS 56식(Microsoft, IBM과 합산, 개별 수량 비공개)
    • Redhat Ent (Red Hat Enterprise Linux) — 공개SW 503식 내 OS 항목(개별 수량 비공개)
    • Jboss — 상용 WAS/WEB 47식 내(개별 수량 비공개)
    • Jboss EAP — 공개SW 503식 내 WAS/WEB 항목(개별 수량 비공개)
    • ※ 커뮤니티 제품(높음 근거 아님): CentOS, WildFly
  • RHEL·JBoss EAP 서브스크립션 갱신: 기 도입 상용 Red Hat 스택의 유지관리 대상 명시 → MAR-004(패치·업데이트·라이선스 관리), MAR-012(원공급사 기술지원·기술지원확약서), PSR-005(오픈소스 라이선스 관리) 근거로 정식 서브스크립션 갱신 필요성 강조
  • CentOS → RHEL 전환: CentOS EOL에 따른 보안패치 부재로 SER-005 보안취약점 조치 요구 충족 곤란 → RHEL(Convert2RHEL 활용) 전환 제안
  • WildFly/Tomcat → JBoss EAP: 공개 WAS의 장애조치·패치 책임 문제 해결 위해 상용 지원 EAP로 표준화 제안
  • 클라우드(가상화)·PaaS: MAR-005의 템플릿·PaaS 이미지 유지관리, 레거시→클라우드 전환 요구 → OpenShift(OCP), OpenShift Virtualization(VMware 대체) 제안 여지
  • 자동화: 7대 예방점검·일상점검(매일), 패치, 보안취약점 조치, 구성·변경관리 → Ansible Automation Platform으로 9명 상주인력 운영 효율화 / Satellite로 대규모 RHEL 패치·구성 관리
  • 평가 가점 연계: '제조사(국내총판) 협력방안'(3점), '공개/상용 SW 유지관리 방안'(4점) 항목에 Red Hat 공식 파트너 협력체계·기술지원확약서로 입찰 SI의 경쟁력 강화 지원
  • 영업 전략: 입찰 예정 중소·중견 SI 대상 사전 파트너링, 보안서약 후 현장 열람을 통한 RHEL/JBoss 실수량 파악 및 갱신 견적 반영 권고
