  • Red Hat 상용 제품명 전혀 미명시: RFP 및 SW 목록 전체에 RHEL, OpenShift, Ansible, JBoss EAP, Satellite 등 Red Hat 상용 제품이 단 한 건도 품목으로 명시되지 않음

  • AI 프레임워크 전량 오픈소스 확정: PyTorch, TensorFlow, MLflow, Kubeflow, Airflow, Hugging Face Transformers 등 전 AI SW가 오픈소스로 확정되어 Red Hat 상용 AI 플랫폼 대체 어려움
  • G-Cloud(공공클라우드) 기반 개발·운영 환경: 1~2차년도 개발·학습 인프라는 CSAP 인증 공공클라우드 사업자가 제공 — Red Hat이 인프라 OS 레이어에 개입하기 어려운 구조
  • LLM 오픈소스 모델 사용 확정: LLaMA 3.x, Qwen2.5 등 오픈소스 LLM 사용으로 Red Hat OpenShift AI 상용 라이선스 필요성 낮음
  • 경쟁·대체 OS 명시 없음: VMware, Ubuntu, Oracle Linux, Rocky Linux 등 경쟁 제품이 명시되지는 않았으나, 반대로 Red Hat 상용 제품도 명시 없음
  • S/W는 포함되나 Red Hat 납품 항목 없음: SW 납품이 있는 사업이지만 Red Hat 상용 제품이 품목 목록에 없어 직접적인 판매 기회 부재

    • ECR-002의 "Linux DB암호화/접근제어 서버" 언급 → RHEL 기반 구성 제안 여지
  • [컨테이너 플랫폼 — OpenShift 전환 제안 여지]
    • ECR-006에서 "컨테이너(Docker/K8S) 기반 이식형 아키텍처 준수" 명시 → 3차년도 온프레미스 이관 시 OpenShift Container Platform 전환 제안 가능

  • [MLOps 자동화 — Ansible/OpenShift AI 제안 여지]
    • MLOps 파이프라인, 모델 배포·버전관리·재학습 자동화 요구(ECR-005, SFR-007) → Ansible Automation Platform(AAP)을 통한 인프라 자동화 운영 제안 가능
    • Kubeflow 기반 AI 파이프라인 요구 → Red Hat OpenShift AI(OpenShift 위 Kubeflow/Open Data Hub 기반) 솔루션 제안 연계 가능성 검토
  • [보안·운영 — Satellite, AAP 활용 여지]
    • 보안패치 정기 적용(SER-010), 형상관리, 운영 자동화 요구 → Red Hat Satellite(서버 패치 관리) 및 Ansible(자동화) 제안 가능
