불가능 요소
  • S/W 공급 범위 제한: 본 사업은 AI 애플리케이션 개발·고도화 용역 중심이며, Red Hat 제품(RHEL, OpenShift, Ansible 등)의 명시적 구매·도입 요구사항이 없음
  • 통합발주 S/W: 유일하게 명시된 통합발주 S/W는 「문서 공동 편집 SW 1식」으로 Red Hat 제품군과 무관한 협업·편집 솔루션 영역
  • 경쟁·기존 기술 고정: 현행 HCX-007(24B) LLM 기반 운영체계가 전제되며, 멀티모델·sLLM은 제안사 선정·협의 방식으로 오픈소스 LLM 추가 도입 구조 → Red Hat AI/LLM 스택 직접 지정 없음
  • 인프라·HW: GPU 서버(H100) 등 하드웨어는 기존 인프라 활용·배분 관리 중심으로, OS·가상화·컨테이너 플랫폼에 대한 Red Hat 제품 지정 없음(기술적용계획표에서 Linux는 선택 항목)
  • 평가·사업 성격: 기술평가 90점 중 생성형AI·RAG·LLM/sLLM 성능(10점) 및 SW 개발 역량이 핵심이며, Red Hat 플랫폼 역량 평가 항목 없음. 중소 SW 개발사업자 대상 협상입찰
Red Hat 제안
가능 요소
  • RHEL: On-premise GPU 서버(H100) 운영환경의 Linux OS 후보로 기술적용계획표에 Linux가 서버용 개방형 OS로 언급되어 있으나, 필수 지정은 아님 → 제안사 제안 범위 내 간접 기회
  • OpenShift/OpenShift AI: 멀티 AI모델 GPU 자원 배분·스케줄링, 컨테이너 기반 sLLM·RAG 서비스 운영 요구와 부합하나 RFP에 명시되지 않아 제안사(개발사)를 통한 옵션 제안 수준
  • Ansible: RPA·ETL 파이프라인·GPU 스케줄링 등 운영 자동화 요구와 연계 가능하나, RFP에 자동화 도구 지정 없음
  • 보안·컴플라이언스: 개인정보 마스킹, 접근통제, 보안취약점 진단, On-premise 폐쇄망 운영 등 Red Hat Enterprise Linux 보안·컴플라이언스 강점과 부합하나 직접 조달 대상 아님
  • 협력 경로: Red Hat 직접 입찰보다는 AI·SI 제안사(SW 개발사) 파트너십을 통한 OS·컨테이너·AI 플랫폼 레퍼런스 아키텍처 제안 방식이 현실적
