불가능 요소
  • S/W 공급 주체: 클라우드용 S/W는 국정자원 제공 및 관리원 직접구매 예정이며, 사업자는 설치·호환성 검증·설정 지원만 수행 → Red Hat 제품 라이선스 직접 공급 기회 제한
  • 경쟁·대체 제품 명시: DBMS는 Oracle→EDB(EnterpriseDB) 전환 명시, RHEL·PostgreSQL 등 Red Hat DB 대안 미명시
  • WEB 서버: Apache로 전환 명시, Red Hat 제품과 무관
  • 상용 SW 고정: SSO(Pass-Ni), DB암호화(MagicDBPlus), 인증(MagicLine) 등 국산 상용 SW가 지정되어 Red Hat Identity/SSO 대체 불가
  • 사업 성격: 정보시스템 개발·이전 용역(SI) 중심으로 HW·OS·클라우드 인프라는 국정자원 대구센터가 제공·관리
  • 입찰 제한: 중소 SW사업자 전용(20억 미만), 대기업·중견기업 참여 불가 → Red Hat 직접 수주 구조 부적합
Red Hat 제안
가능 요소
  • JBoss EAP (핵심 기회): SFR-009·SFR-011에서 WAS를 JEUS→JBoss-EAP로 이기종 전환 명시, AP 튜닝·설치 지원 필요 → JBoss EAP 구독·기술지원·마이그레이션 컨설팅 제안 가능
  • RHEL 연계: 기술적용계획표에 Linux 서버 OS 적용 계획, 국정자원 클라우드 환경 OS 전환 협의 항목 존재 → RHEL 기반 운영체제·컨테이너 표준화 제안 여지
  • Ansible: 클라우드 이전·다수 단위업무·이원화 시스템 안정화, 패치·설정 자동화, DR/백업 프로세스에 인프라 자동화 솔루션 제안 가능
  • 파트너 협력: 하도급 허용(50% 이내), 공동수급 가능 → 낙찰 SI사업자에 Red Hat 제품·기술지원을 하도급/협력 형태로 공급
  • 기술 요구 정합: 고가용성·성능튜닝·보안강화·24시간 운영·연계테스트 요구와 Red Hat 엔터프라이즈 지원 체계 부합, JEUS→JBoss-EAP 전환 시 Red Hat 공식 마이그레이션 방법론 활용 가능
