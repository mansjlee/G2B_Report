Red Hat 제안
불가능 요소
  • Ubuntu OS 명시: RFP 나. 안심존 인프라 운영·관리 항목에서 "운영체제(OS)는 리눅스(Ubuntu, CentOS 등)와 Windows 운영체제를 제공해야 하며 해당 소프트웨어 라이선스 확보 필요"라고 명시. 도커 이미지 8종 모두 Ubuntu 18.04/20.04/22.04 기반으로 구성되어 있으며, RHEL 등 Red Hat 상용 제품에 대한 언급 없음
  • CentOS 언급(참고용): "Ubuntu, CentOS 등"으로 병기되어 있으나, 실제 운영 도커 이미지는 Ubuntu로만 구성. CentOS는 커뮤니티 제품으로 높음 판정 불가
  • Red Hat 상용 제품 미명시: RFP 전반에 걸쳐 RHEL, OpenShift, Ansible, JBoss EAP, Satellite 등 Red Hat 상용 제품명이 단 한 차례도 품목·유지보수 대상·현행 시스템 구성으로 등장하지 않음
  • 순수 운영·유지관리 용역 성격: S/W 통합발주 또는 조달쇼핑몰 직접구매 품목이 별도로 없으며, 클라우드 인프라 비용 및 라이선스 비용은 수행사가 자체 조달하는 구조. Red Hat 구독 도입이 명시된 항목 없음
  • 컨테이너 플랫폼 미지정: Docker 이미지 관리가 요구되나 OpenShift/OCP 등 특정 컨테이너 플랫폼이 지정되지 않았고, 오픈소스 기반 솔루션 활용을 권고하는 방향(오픈소스를 통한 자체기능 제공 또는 GPUaaS 서비스 등)
  • 중소 SW사업자 제한: 20억 미만 사업으로 중소 SW사업자만 입찰 가능. Red Hat이 직접 입찰 불가한 구조이며, 파트너사를 통한 납품 항목도 미명시
Red Hat 제안
가능 요소
  • RFP 내 Red Hat 상용 제품명 명시 없음: RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품이 도입·납품·유지보수 대상으로 전혀 명시되지 않아 직접적인 제안 근거 없음
  • Linux 계열 OS 제안 여지 (매우 제한적): RFP에서 "Ubuntu, CentOS 등" Linux를 명시하고 있어 RHEL 제안 가능성이 거의 없음. Ubuntu가 사실상 확정 OS로 운영 중이며, 도커 이미지 8종 모두 Ubuntu 기반. 수행사가 OS 라이선스를 자체 조달하는 구조이므로 RHEL로의 대체 가능성 극히 낮음
  • 컨테이너/클라우드 운영 환경: Docker 기반 컨테이너 이미지 관리, 클라우드 인프라 운영, Kubernetes/플랫폼 연계 등의 요소가 있어 이론적으로 OpenShift 제안 여지가 있으나, RFP가 오픈소스 기반 자체 구성을 권고하고 있어 실질적 가능성 낮음
  • Ansible 자동화 제안 여지 (참고): GPU 자원 동적 할당·관리, 인프라 자동화, 보안 패치 관리 등의 요구사항은 Ansible Automation Platform 적용 가능 영역이나, 수행사 재량 범위이며 RFP에 명시되지 않음
  • 종합 평가: 본 사업은 Ubuntu OS가 명시된 운영·유지관리 용역으로, Red Hat 상용 제품 도입·납품 항목이 전혀 없음. 판정 규칙상 "Ubuntu OS 명시, S/W 미포함 용역" 조건에 해당하여 낮음으로 판정. 현 시점에서 Red Hat 영업 기회로 보기 어려우며, 향후 차년도 사업 발주 시 인프라 OS 전환 가능성을 모니터링하는 수준이 적절함
