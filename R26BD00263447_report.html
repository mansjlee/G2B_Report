Red Hat 제안
불가능 요소
  • WildFly(커뮤니티/업스트림 제품) WAS로 명시: WAS 항목에 WildFly × 1식이 이미 확정 도입 대상으로 명시되어 있어 JBoss EAP 상용 제품으로의 신규 교체는 현실적으로 어려움 (기존 시스템 유지보수 사업 특성상 교체 유연성 낮음)
  • CentOS CS(HA) DBMS 이중화솔루션으로 명시: CentOS는 커뮤니티 제품으로 RHEL 상용 품목 근거 불가. 해당 항목이 이중화 솔루션명으로 고정되어 있어 단기 RHEL 전환 어려움
  • Red Hat 상용 제품명 전혀 없음: RHEL, OpenShift, Ansible, JBoss EAP 등 Red Hat 상용 제품명이 RFP 어디에도 명시되지 않음
  • 순수 유지보수 용역 중심: 신규 SW 도입·구축보다는 기존 시스템의 유지관리·라이선스 갱신이 주된 사업 목적으로, Red Hat 신규 상용 제품 납품 기회가 제한적
  • 대기업 참여 불가: 사업금액 20억 미만으로 대기업 소프트웨어 사업자 입찰 참여 불가 — Red Hat이 직접 또는 대형 파트너를 통해 접근하기 어려운 구조
  • 알약 리눅스 서버 백신 86식 도입: Linux 서버 보안 솔루션으로 타사 제품(알약)이 이미 확정되어 RHEL 기반 보안 솔루션 제안 공간 축소
Red Hat 제안
가능 요소
  • Docker & Kubernetes 운영 환경 → OpenShift 제안 여지: MAR-010(오픈랩), MAR-012(개인정보 영상 비식별화)에서 "도커&쿠버네티스" 기반 시스템 운영이 명시되어 있어, OpenShift Container Platform 또는 OpenShift AI 제안의 기술적 기반이 존재함
  • WildFly → JBoss EAP 전환 제안 여지: 현재 WildFly(커뮤니티)가 WAS로 운영 중이므로, 엔터프라이즈 지원·보안 패치·장기 라이프사이클이 필요한 공공기관 특성상 JBoss EAP(상용) 전환 제안 가능
  • CentOS CS(HA) → RHEL 전환 제안 여지: CentOS의 지원 종료(EoL) 이슈를 근거로 RHEL 기반 HA 클러스터로의 전환을 차기 사업 또는 증설 시 제안 가능. 서버 백신이 "알약 리눅스" 86식임을 감안할 때 다수의 Linux 서버가 운영 중임을 확인
  • Linux 서버 대규모 운영 환경: 서버 229식 규모의 인프라에서 Linux 계열 OS가 상당수 사용 중으로 추정(알약 리눅스 백신 86식 근거). RHEL 도입 또는 Satellite 기반 패치 관리 자동화 제안 가능
  • Nifi, Kafka 빅데이터 플랫폼 → AMQ/Fuse 제안 여지: MAR-009에서 Nifi·Kafka 기반 데이터 수집·적재 운영이 명시되어 있어, Red Hat AMQ Streams(Kafka 상용) 또는 Red Hat Fuse 기반 데이터 통합 플랫폼 전환 제안 가능
  • Ansible 자동화 제안 여지: HW 39종·SW 22종 규모의 이기종 복합 인프라에 대한 패치·점검·설정 관리 자동화 수요가 명확하여 Ansible Automation Platform(AAP) 도입 제안 가능
  • RFP에 명시된 Red Hat(또는 동의어) 상용 제품명: 해당 없음 — WildFly(커뮤니티), CentOS(커뮤니티)만 명시되어 있으며 Red Hat 상용 제품명은 문서 내에 전혀 없음
