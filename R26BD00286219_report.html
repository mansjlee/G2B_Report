Red Hat 제안
불가능 요소
  • 신규 S/W 직접구매 아님: 본 사업은 신규 SW 조달청 직접구매가 아닌 위탁운영·유지보수 사업으로, 상용SW 라이선스 비용은 제안사(수행업체)가 부담하는 구조임 → Red Hat이 직접 입찰하기 어렵고 SI·용역사업자를 통한 간접 판매 구조
  • DB 경쟁 제품 확정: DB는 Cubrid(한국산 RDBMS)로 이미 확정·운영 중, RHEL 기반 RH Data Grid·AMQ 등의 제안 공간 협소
  • 검색엔진 경쟁 제품 확정: 검색엔진은 Search Formula-1으로 확정 운영 중, OpenSearch/RH 기반 전환 여지 낮음
  • AI 인프라 비용 발주기관 부담: 대구센터 PPP존 AI 관련 인프라(Vector DB·Graph DB·GPU 서버 등) 비용은 발주기관이 직접 부담하며 별도 CSP·MSP 계약으로 운영됨 → 해당 영역 Red Hat 신규 제안 불가
  • OS 미확인(보안상 생략): 일부 서버 OS가 '보안상 생략'으로 명기되어 있어 경쟁 OS(Rocky Linux 등) 운영 여부 확인 불가
  • 20억 미만 중소기업 사업: Red Hat Korea가 직접 수행 불가한 구조이며, Red Hat 파트너사(중소 SI)를 통해서만 참여 가능
Red Hat 제안
가능 요소
  • 🔴 [핵심] JBoss (JBoss EAP) — Red Hat 상용 제품 명시·운영 중
    • 시스템 현황표에 WEB 및 WAS로 JBOSS가 명시되어 현재 운영 중
    • MAR-005(상용SW 유지보수) 조항: "상용SW의 라이선스 및 각각의 유지보수 계약은 제안사의 부담으로 한다" → 수행업체가 JBoss EAP 구독·유지보수 계약을 체결해야 하므로 Red Hat 직접 매출 발생 가능
    • SLA 선택지표에 상용SW 지원체계 유지율(목표 100%) 포함 → JBoss EAP 라이선스 유효성·기술지원 유효성·EOS/EOL 관리가 SLA 평가 항목으로 직결됨
    • 수량: 보안상 생략(방문 열람 가능)
  • OS Linux — RHEL 제안 여지
    • 기존 SW 구성표에 OS가 'Linux'로만 기재되어 배포판 미확정(상세 내역 보안상 생략)
    • JBoss EAP와 함께 RHEL 구독 제안 시 지원 일관성·공식 스택 활용 가능
  • AI 인프라 — OpenShift·Ansible 제안 여지
    • LLM 추론·RAG 파이프라인·Vector DB·Graph DB 운영을 위한 컨테이너 오케스트레이션 환경에 OpenShift Container Platform(OCP) 또는 OpenShift AI 제안 가능
    • LLMOps 기반 모델 버전관리·배포 자동화에 Ansible Automation Platform(AAP) 활용 제안 가능
    • 단, 현재 대구센터 AI 인프라 비용은 발주기관 부담으로 별도 계약 추진 필요
  • RFP 내 Red Hat(동의어) 제품 명시 현황 정리
    • JBOSS (WEB) — 수량 보안상 생략, 현재 운영 중 (JBoss EAP = Red Hat 상용 제품)
    • JBOSS (WAS) — 수량 보안상 생략, 현재 운영 중 (JBoss EAP = Red Hat 상용 제품)
  • 영업 액션 포인트: 수행 SI 파트너사 대상으로 JBoss EAP 구독 갱신 및 RHEL 제안을 사전 조율할 것. SLA 상용SW 지원체계 유지율 항목이 JBoss 라이선스 유효성과 직결되므로 파트너 영업 레버리지로 활용 가능
